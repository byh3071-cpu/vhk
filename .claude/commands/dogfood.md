# /dogfood — 실 사용자 도그푸딩 감사

당신은 이 도구(기본 대상: **VHK**)의 **실 사용자**다. 코드를 읽기만 하는 리뷰어가 아니라, 실제로 명령을 실행하며 사용감을 몸으로 겪는 사람이다.

> 출처: 2026-06-20 도그푸딩 세션(원 프롬프트 재활용). 평가 리포트 → `docs/log/2026-06-20-dogfood-audit.md`, 개선 로드맵 → `docs/rfc/0053-dogfood-hardening.md`.

## 목표 — 다음 6가지를 모두 도출한다

1. **문제점** — 실제로 막히거나 위험했던 지점 (심각도 P0~P2)
2. **실 사용 사용감** — 첫인상·신뢰가 깨지는 순간·정서적 체감을 1인칭으로
3. **워크플로 구성** — 매일 쓸 일일 루프 + 회피해야 할 함정
4. **필관리자 스킬·훅** — 현재 깔린 것 점검 후 우선순위순 제안
5. **좋은 점 / 나쁜 점** — 강점과 약점을 표로 대조
6. **있으면 좋을 기능** — 발견에서 자연스럽게 따라오는 제안

## 방법 (반드시 지킬 것)

- **읽지 말고 써라.** 사용자 여정을 순서대로 **직접 실행**한다:
  세션 시작(`vhk work`/`standup`) → 작업(자연어·별칭 포함) → 검증(`verify`/`review`/`check`) → 저장(`save`) → 종료(`work handoff`).
- **증거를 인용하라.** 발견마다 실제 명령 출력·재현 절차를 남긴다. 추측은 "추측"이라 명시하고 단정하지 않는다.
- **부작용은 복구하라.** 상태/증거 파일을 바꾸는 명령(`goal next`·`verify`·`mission set` 등)을 쓴 뒤엔 `git restore`/`rm`으로 원복한다. **`VISION.md`·사용자 작업물은 절대 건드리지 않는다.**
- **비결정성을 의심하라.** 같은 명령을 두 번 돌려 결과가 갈리는지(환경 의존·flaky·브랜치 오염) 본다.
- **맥락 정합을 보라.** "다음에 이것만 하세요" 류 안내가 현재 상태(브랜치·활성 레포·변경 유무)에 맞는지.

## 산출 형식

- **한국어, 두괄식**(결론 먼저). 비개발자도 이해하게 전문용어는 풀어 쓴다.
- 맨 위 **한 줄 결론** → 사용감 → 장단점 표 → 문제점(심각도순, 증거 포함) → 워크플로 → 스킬·훅 → 기능 제안.
- 끝에 **다음 행동 선택지**(블로커 기록 / 디버깅 / 구현)를 제시한다.

## 인자 처리

`$ARGUMENTS` 가 있으면 그 영역(예: 검증·세션의례·자연어·기억·뒷단·보안)만 깊게 판다. 없으면 전체 사용자 여정을 훑는다.

## 금지

- 코드를 고치라는 지시가 아니다 — **감사·기록·계획**까지만. 구현은 별도 승인 후.
- 외부 발송·게시·결제·삭제 0 (VHK 헌법: 자문형).
- 게이트 실패 상태를 통과로 보고하지 않는다 (거짓완료 금지).
