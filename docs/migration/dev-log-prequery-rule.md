# 마이그레이션 가이드 — 기존 프로젝트에 "사전 조회 규칙" 추가

> 양방향 루프(수집 + **회수**)의 회수 측. 새 프로젝트는 `vhk init`(템플릿 소스 `src/templates/claude-md.ts`)이 이 섹션을 자동 삽입하므로 **이 가이드가 필요 없다**. 이미 `CLAUDE.md`가 있는 **기존 프로젝트**만 1회 수동 추가하면 된다.

## 왜
Dev Log DB / 패턴 DB에 쌓인 과거 경험을 새 작업 시작 전에 **먼저 조회**해 재사용한다. 이 규칙이 `CLAUDE.md`에 박혀 있어야 에이전트가 "과거를 알고" 시작한다(없으면 매번 맨바닥).

## 적용 대상
- 이미 `CLAUDE.md`가 있는 기존 프로젝트 (vhk init 이전 생성분)
- 한 번만 하면 됨 (멱등 — 이미 있으면 스킵)

## 단계
1. 프로젝트 루트의 `CLAUDE.md`를 연다.
2. 이미 `## 사전 조회 규칙` 섹션이 있으면 **중단**(중복 추가 금지).
3. 없으면, 기존 `## 기록 규칙`(또는 그에 준하는 기록 섹션) **바로 앞**에 아래 블록을 붙여넣는다. 기록 섹션이 없으면 파일 상단 메타 직후에 둔다.
4. 저장. 다음 세션부터 에이전트가 시작 전 조회한다.

## 붙여넣을 블록 (정본 — `src/templates/claude-md.ts` 출력과 동일)
```markdown
## 사전 조회 규칙 (Dev Log DB 연동)
기록하기 전에 **먼저 조회**한다 — 과거 경험을 재사용(양방향 루프의 회수 측).
- **새 프로젝트 시작 · 에러 발생 · 기술 선택** 시 Dev Log DB를 먼저 조회한다.
- 관련 기록이 있으면 **핸드오프 스냅샷**을 요청한다.
- 조회 결과는 `docs/state/handoff.md` 에 반영한다.
```

## 조회를 실제로 어떻게 하나
- **런타임 가능 시 (권장):** yohan-mcp `get_context` 도구 호출. `opts`에 `project`(필수), 선택적으로 `category`/`tags`를 넘기면 Dev Log 행(`devlog_query`) + 재사용 패턴(`pattern_query`)이 컨텍스트에 함께 주입된다. *(ADR-008 — get_context 통일 타깃 = yohan-mcp Python. 이 배선은 완료됨.)*
  - 전제: 머신 환경변수 `NOTION_TOKEN` + `NOTION_DEVLOG_DB_ID` + `NOTION_PATTERN_DB_ID` 설정.
  - 프로젝트명이 없으면 빈 배열(에러 아님), 토큰 없으면 명확한 에러.
- **런타임 미가용 시:** 요한에게 **핸드오프 스냅샷**을 요청해 `docs/state/handoff.md`에 반영한 뒤 시작.

## 검증
- `CLAUDE.md`에 `## 사전 조회 규칙` 섹션이 1개 있는가(중복 0)?
- 새 세션에서 에이전트가 작업 착수 전 Dev Log/패턴을 조회하는가?

## 참고
- 정본 섹션을 바꾸려면 `src/templates/claude-md.ts`를 고친다(새 프로젝트 전파). 이 가이드의 블록도 동일하게 맞춘다.
- 관련: 양방향 루프 진단·핸드오프(노션), ADR-008(yohan-brain — get_context 배선).
