# ADR-009: 자율화 구현 타깃 = vhk-auto 계약 확장 (신규 모듈 아님)

- 상태: 승인 (오너 결정 2026-07-27)
- 결정자: 요한 (딥리서치 결정 5 권고 채택)
- 근거 SoT: yohan-brain `docs/yohanthinking/research/2026-07-27--vhk-autonomous-agent-deepresearch.md` (PR yohan-brain#143, 머지됨)

## 맥락

RFC 0054 D2(외부 집행)는 이연 상태이며 재개 3조건(측정된 신뢰·병목 입증·오너 결정) 미충족. 그러나 재개 시 구현 타깃(기존 vhk-auto 계약 확장 vs 신규 autonomous 모듈)을 미리 확정해 두어야 계측 설계(goal 110·111)가 올바른 스키마 위에 쌓인다.

## 결정

**`vhk auto`는 신규 서브커맨드로 추가하되, 내부는 기존 verify·receipt·HARD_STOP·autonomy-log를 그대로 게이트로 쓰는 "집행 레인 추가" 구조로 한다. 별도 autonomous 모듈은 만들지 않는다.**

1. 순서: 외부 집행 기능보다 **승급 계측·게이트 관리**(레벨 조회·승급 판정·강등·리스크 티어 레인 정의)를 먼저 구현한다.
2. 집행 상한: **push+PR까지, 머지 제외** — overnight conductor의 현 계약과 동일 상한 유지.
3. 리스크 티어 레인: 자동 허용 유형 allowlist(chore·docs·deps) / 사람 필수(스키마·보안·인증) — 기존 하드 트리거와 정합.
4. 안전 계약(집행 레인 구현 시): 명령 allowlist + 사전실행 결정론 게이트 + 실행 후 출력 검증 병행 + 예산·시간 한도는 요청 경로에서 이중 집행.

## 근거 (리서치 결정 5)

- 재개 표준 = 외부 append-only 이벤트로그+체크포인트+git 커밋 경계, "워커는 SoT가 아니다" — VHK autonomy-log·handoff가 이미 이 표준. 신규 모듈은 게이트 중복 구현으로 이중 SoT 위험.
- 업계 패턴: 자율성 다이얼 = 기존 도구의 모드 확장(Claude Code 권한 모드·Codex 승인 모드·Factory 다이얼), 신규 모듈 분리 사례 없음.
- 4기준 대조: ②기존 게이트 재사용도·④GA 시그니처 보존(신규 커맨드 추가로 자동 충족) = 확장 우세 / ①INV 확장 필요·③티어 레인 신설 = 동률.
- 무인 머지는 업계에서도 극소수 개방 + 체크 위조 공격 존재 — 상한 PR까지의 근거.

## 결과

- goal 110(complete 판정 강화)·111(병목 계측 3종)는 이 결정을 전제로 autonomy-log 스키마 위에 설계한다.
- D2 재개 판정 자체는 별도(4주 계측 후 오너) — 본 ADR은 "재개된다면 어디에"만 확정.
- 되돌리기: 계측 단계에서 확장 노선의 구조적 결함이 드러나면 본 ADR을 개정한다(스키마는 autonomy-log 소유라 노선 변경에도 재사용 가능).
