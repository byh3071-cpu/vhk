# ADR-010: 작업 항목의 원본은 추적되는 문서에 두고, 공개 경계 규칙을 그에 맞게 좁힌다

> 용어: ADR-011 대응표 참조.

## 맥락 (Context)

ADR-008(공개 경계 분리)에 따라 2026-07-27 이력 재작성으로 `goals/`·`docs/state/`·`docs/log/`가 공개 저장소에서 제거됐다. 규칙 문구는 이렇다.

> 공개 추적 금지: 개인 운영 로그·상태·**goal**, 로컬 절대경로, 개인 이메일, 실명, 개인 저장소명, 실제 외부 서비스 객체 ID

정리 자체는 옳았으나 세 가지 부작용이 남았다.

1. **작업 항목의 원본이 사라졌다.** goal 카드 32장의 유일한 사본이 `.gitignore`된 worktree 안에만 있었다. worktree 정리 한 번이면 영구 소실되는 상태였다.
2. **`vhk goal` 전체가 무동작이 됐다.** `src/commands/goal.ts:24`가 `goals/`를 하드코딩하는데 디렉터리가 없어 모든 서브커맨드가 "goal 0개" 분기로 빠졌다. 검사 스크립트도 함께 사라져 `goal done`이 구조적으로 불가능해졌다.
3. **규칙과 실무가 어긋나 있다.** 같은 저장소의 GitHub 이슈에는 작업 항목 17건이 이미 공개돼 있다. 즉 "작업 항목 비공개"는 선언만 됐고 지켜지지 않는다.

여기에 운영 요구가 하나 더 있다. 관리자는 여러 대의 기기에서 작업하며 수동 동기화를 한다. 작업 항목이 추적되지 않으면 기기를 옮길 때마다 상태가 끊긴다.

## 결정 (Decision)

### 1. 규칙 문구를 좁힌다

ADR-008의 "공개 추적 금지: …goal" 을 다음으로 대체한다.

> 공개 추적 금지: **개인 운영 기록**(세션 로그·개인 일정·가용시간·개인 사정), 로컬 절대경로, 개인 이메일, 실명, 개인 저장소명, 실제 외부 서비스 객체 ID
>
> 공개 추적 허용: **제품 작업 항목**(로드맵·릴리스 계획·작업 단위와 그 완료 조건) — 단 위 금지 항목을 하나도 포함하지 않을 때만.

근거는 규칙의 취지다. ADR-008이 막으려던 것은 개인 식별자와 개인 운영 상태이지, 오픈소스 저장소의 작업 목록이 아니다. 작업 목록은 오픈소스에서 공개가 기본이고, 이 저장소도 이미 이슈로 공개하고 있다.

### 2. 원본과 파생물을 분리한다

| 층 | 무엇 | 추적 | 소실 시 |
|---|---|---|---|
| **원본** | `docs/roadmap/2.x-roadmap.md` + `docs/PRD-2.x.md` — 작업 항목과 그 완료 조건 전량 | 추적 | — |
| 파생 | `goals/*.md` 카드 — `vhk goal check`/`done`이 읽는 실행 단위 | 비추적 | 원본에서 재생성 |
| 파생 | `scripts/check-goal-<번호>.mjs` — 카드에 대응하는 검사 스크립트 | 비추적 | `vhk goal sync` 백필 |

카드와 검사 스크립트를 같은 단위로 묶는다. 카드가 비추적이면 그 검사 스크립트도 비추적이다. 실제로 `scripts/check-goal-92.mjs`는 2.12.0에서 제거된 개인 결합 설정을 참조하고 있어 `pnpm boundary:check`를 실패시킨다 — 이 분류가 그 사고를 구조적으로 막는다.

`scripts/check-goal-frontmatter.mjs`처럼 번호가 아닌 이름을 가진 스크립트는 제품 검사이므로 계속 추적한다.

### 3. 진입점을 배선한다

원본 문서를 만들어두는 것만으로는 아무도 읽지 않는다. 2차 도그푸딩 25시간 실측이 이를 확인했다 — `docs/state/next-task.md`가 14시간 동안 낡은 채로, 그것도 틀린 내용으로 방치됐다.

따라서 `RULES.md`에 현 사이클 원본 문서의 경로를 명시하고 `vhk sync`로 규칙 파일 8종에 전파한다. 어떤 도구로 세션을 열든 자기 규칙 파일에서 그 경로를 읽게 된다.

## 대안 (Alternatives)

| 안 | 내용 | 기각 사유 |
|---|---|---|
| A | GitHub 이슈를 원본으로 | 규칙 개정이 불필요하고 기기 동기화도 자동이다. 다만 이슈는 오프라인에서 안 읽히고, `vhk goal`이 읽는 형식과 달라 변환 계층이 필요하다. **폐기하지 않고 병행 수단으로 남긴다** — 이 ADR이 뒤집히면 이쪽으로 간다 |
| B | 현행 유지(카드 비추적 + gist 백업) | 백업·복원을 사람이 의식해야 한다. 도그푸딩 결론("사람이 다시 불러야 하는 것은 죽는다")에 정면으로 걸린다 |
| **C** | **문서를 원본으로 + 규칙 개정 (채택)** | 규칙을 몰래 어기지 않고 명시적으로 개정한다 |

## 결과 (Consequences)

**긍정**

- 카드가 소실돼도 원본 문서에서 재생성된다. 유일 사본 위험이 사라진다.
- 기기 이동이 `git pull` 하나로 끝난다.
- 규칙과 실무(공개 이슈 17건)의 모순이 해소된다.

**부정 / 비용**

- 로드맵 문서에 무엇을 쓸 수 있는지 판단이 매번 필요하다. → 금지 항목이 열거형이고 `pnpm boundary:check`가 기계 검사하므로 판단 비용은 낮다.
- ADR-008을 부분 개정하는 첫 사례다. append-only 원칙상 ADR-008 본문은 그대로 두고 이 ADR이 해당 조항을 대체한다.

**되돌리기**

이 결정이 틀린 것으로 드러나면(예: 로드맵 문서에서 개인 정보 유출 사고 발생) 대안 A로 전환한다. 작업 항목의 내용은 형식 무관하게 이전 가능하므로 전환 비용은 문서 1장 분량이다.

**관련**

- 실행 단위: goal 112(관리 체계 복구)·113(진입점 배선, 릴리스 위생) — 2.x 로드맵 R0.
- ADR-008의 나머지 조항(독립 동작 CLI, 규칙 소스 분리, 이력 재작성 사람 승인)은 전부 유효하다.
