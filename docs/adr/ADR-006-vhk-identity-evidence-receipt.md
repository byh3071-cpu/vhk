# ADR-006 — VHK 정체성 확정: Evidence Receipt (멀티툴 솔로용 거짓완료 탐지기)

- 상태: Accepted
- 날짜: 2026-06-22
- 관련: RFC 0055(Proof Protocol — Codex 제안, §13에서 다차원 검증), RFC 0056(Evidence Receipt 전략), RFC 0054(자율형 진화), SOUL.md, #315

## 맥락

RFC 0055는 Codex에게 물어 나온 "VHK Proof Protocol = AI 작업 신뢰 원장 → Public 표준" 제안이었다. 다차원 적대 검증(0055 §13, 38건 확정)에서 전략 토대 두 곳이 무너졌다:

1. **순서 역전** — 표준화는 "이미 채택된 것을 고정"인데, 채택 0·구현 0(src에 proof/task/export 전무)·검증기 단일종속 상태에서 표준을 선언했다.
2. **과대약속** — 기반 `vhk review`조차 "보장 아닌 신뢰도 신호, 통과해도 거짓완료 가능"이라 자인하는데, 이를 'Proof(증명)'로 격상하고 "No proof, no ship"으로 팔았다.

여기에 더해 §7(6인 인간 역할 팀)·§8(표준화 야심)이 **실제 운영 현실(1인 비개발자 오너 + AI 에이전트, RFC 0054 자율형 1인 팔란티어)**과 정면 모순했다. 즉 VHK의 방향성·정체성을 다시 잡을 필요가 명확했다.

이를 위해 `vhk-winning-strategy` workflow로 6개 전략 후보(증거영수증·납품증명서·출고검문소·휴대용두뇌·블랙박스·관제탑)를 4렌즈(해자·실행·수요·정합)로 적대평가했다.

## 결정

**VHK의 정체성을 "Evidence Receipt — 에이전트의 '됐어요'를 기계증거 영수증으로 바꾸는, 멀티툴 솔로용 무설정 거짓완료 탐지기"로 확정한다.** 상세 전략은 RFC 0056.

핵심 결정 사항:

- **정체성 한 문장**: "AI가 '됐어요'라고 말한 순간, 종료코드·dirty·SHA 같은 기계증거만으로(LLM 판단 0) 진짜인지 1초에 따진다."
- **명명 격하**: 'Proof(증명)' → **'Evidence(증거)'**. "표준"·"증명서"·"검수필증" 등 보증 톤 단어 금지 — review가 자인한 비보증성과 톤 일치.
- **1차 타겟**: 세그먼트 B(멀티툴 CLI 에이전트 헤비유저). C(납품)=2순위 확장축, A·D=회피.
- **90일 쐐기**: 명령 하나 `vhk receipt`(4대 기계증거 → `.vhk/receipts/<id>.{json,md}` + 결정론 block). 기존 자산 글루코드.
- **90일 단일 성공기준**: "거짓완료 적발 1건 공개입증"(현재 0/8 → 1건). 수익·표준 아님.
- **RFC 0055 §8/§7 폐기**: 표준화 → "도그푸딩 효과입증 → 채택 관찰" 2단 / 6인 팀 → "1인 오너 + 에이전트 + 1 goal=1 PR, 규율은 코드로 박는다".

## 대안 (기각)

전략 workflow 4렌즈 점수순. 승자(5.3/10)조차 "이김 보장"이 아니라 "6개 중 최선 + 결함 정직 흡수"임을 명시한다(니치, 킬 조건으로 빠른 검증 전제).

- **납품 증명서(5.3, kill 1)** — 해자 다수 미구현 + 발급자↔수령자 양면시장 콜드스타트를 1인이 못 깸. 단 "납품 경계에선 고객=제3자 지불"이라는 지불의사 통찰은 수익화 단계에서 차용.
- **출고검문소/GitHub 체크(5.0, kill 2)** — self-bypass·#315 '늘 빨강'·수요 kill. 단 "게이트 대체가 아니라 입주"는 시즌2 배포표면으로 차용.
- **휴대용 두뇌/sync(4.5, kill 3)** — 가장 약한 자산(sync=흔함)을 쐐기로 격상하고 가장 강한 자산(verify→review)을 버림. 무게중심 역전.
- **블랙박스/부검(4.0, kill 3)** — 핵심 기능(history replay)이 그린필드 + 외부 untrusted 레포 실행이 헌법 정면충돌.
- **관제탑/무인머지(3.8, kill 3)** — auto-merge 실제 G3·G4가 CodeRabbit+LLM이라 "기계증거만"이 자기 구현에서 거짓 = 정체성 모순.

또한 **RFC 0055 원안 그대로 승격**도 기각(§13의 high 4건·과대약속·1인 현실 모순).

## 결과

- **RFC 0055는 §13(검증 결과) 하단에서 RFC 0056·ADR-006으로 포인터 연결.** §8/§7 프레임은 0056이 대체. 0055의 객체모델·티켓(§3·§4·§9)은 결함 정정 후 재사용 가능.
- **다음 작업 방향 전환**: 우선순위가 "출시/표준화"가 아니라 **`vhk receipt` MVP(T1~T3) + #315 봉인 + 거짓완료 적발 1건 입증**으로 이동. docs/state/next-task.md 갱신 대상.
- **마케팅·문서 제약(헌법 정합)**: 보증 톤 단어 금지, 산출물에 "기계증거 기반·비보증 경계" 1줄 고정.
- **킬 조건 명문화**: 90일에 적발 0건이면 정직하게 가설 폐기(RFC 0056 §8). measure-first 규율과 정합.
- **미확정(후속)**: receipt JSON 스키마 상세, `.vhk/receipts/` git 추적·마스킹 정책, CI 입주 시점 — RFC 0056 티켓에서 구현 시 결정.

## 정정 노트 (2026-06-23 — 표현 명료화, 결정 불변)

- **"Evidence Receipt"는 전략명·산출물 이름이지 정체성 자체가 아니다.** 정체성 = "인간 의도를 AI에 전달하고, 의도대로 됐나 기계증거로 대조하는 **의도 장갑**"(대화 2026-06-23). `receipt`는 그 검증의 **출력 뷰/영수증**(verify+ledger 조립)이며 이미 #377로 구현됨 — 신규 명령을 정체성으로 거는 게 아니다.
- **간판 동사 = `vhk verify`/`vhk receipt`** (작동 중). receipt MVP(#377)·#315 봉인(#370) 머지 완료.
- **코드 감사로 발견한 빈 고리**: verify/review/receipt가 mission(인간 의도: scope/forbidden)을 **0회 참조** → 의도 장갑의 "검증 면"이 자동 루프에서 빠져 있음. **[Goal 87](../../goals/87-mission-verify-intent-check.md)**로 잇는다(= 해자: 남들은 의도를 모르고 VHK만 안다). 진입점 [dev log 2026-06-23 intent-glove-plan](../log/2026-06-23-intent-glove-plan.md).
- 이 노트는 결정 변경이 아니라 표현 명료화 — 신규 ADR 불필요.
