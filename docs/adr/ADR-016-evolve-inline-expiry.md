# ADR-016: 진화 후보 큐를 실시간 제시와 만료로 대체

## 맥락 (Context)

VHK 자체 프로젝트의 `.vhk/evolve/queue.json`에는 같은 시각에 만들어진 후보 42개가 모두 미판정으로 남았다. 후보를 계속 저장하는 구조는 검토를 돕지 못하고 새 관리 대상만 만들었다. 규칙 후보는 사람이 판단하기 전에는 `RULES.md`에 들어가면 안 되지만, 그렇다고 미판정 목록이 무한히 쌓여서도 안 된다.

## 결정 (Decision)

- 새 후보는 `queue.json`이나 다른 대기 목록에 저장하지 않는다.
- 활성 `memory.patterns`에서 실행할 때마다 후보를 계산한다.
- 후보 ID는 `${patternId}:${targetLayer}`로 고정해 별도 번호 상태를 없앤다.
- 패턴의 `createdAt`부터 7일 동안만 후보를 보여준다. 정확히 7일이 되는 시점부터 만료로 본다.
- 승인·기각은 기존 `.vhk/events/evolve-log.jsonl`에 기록한다. 이전 로그 필드는 그대로 읽고, 되돌리기에 필요한 필드는 선택값으로만 추가한다.
- `vhk evolve suggest --json`과 MCP 조회는 읽기 전용이다.
- `vhk evolve apply <id>`는 TTY와 사람의 명시적 확인을 모두 통과한 경우에만 `RULES.md`를 바꾼다.
- 기존 큐 파일은 프로젝트별 로컬 보관본으로 옮긴다. VHK 자체 후보의 판정 결과를 다른 프로젝트에 재사용하지 않는다.

## 대안 (Alternatives)

- **큐를 유지하고 알림만 강화:** 방치 원인을 없애지 못하고 다시 대기 목록이 쌓인다.
- **새 만료 상태 파일을 추가:** 이름만 다른 큐가 생기므로 제외했다.
- **만료 없이 매번 계산:** 무응답 후보가 계속 반복 노출되므로 제외했다.
- **`apply` 명령 제거:** 가장 보수적이지만 사람이 승인한 뒤에도 직접 파일을 편집해야 한다. TTY와 확인을 강제하는 기존 명령을 유지하는 편이 안전성과 사용성을 함께 지킨다.

## 결과 (Consequences)

- 새 미판정 후보 수는 디스크에 누적되지 않는다.
- 후보 생성일이 잘못된 이전 패턴은 영구 후보가 되지 않도록 표시에서 제외한다.
- 7일이 지나면 후보가 조용히 사라지므로 중요한 제안도 놓칠 수 있다. 필요하면 실제 사용 기록을 근거로 기간만 다시 결정한다.
- 새 후보 ID는 기존 `e1` 형식이 아니라 `p1:rule` 형식이다. 명령과 MCP 이름은 유지하지만 표시 ID는 바뀐다.
- 기존 큐 읽기·마이그레이션 함수는 하위호환과 보관 검증을 위해 남기되 신규 실행 경로에서는 쓰지 않는다.
