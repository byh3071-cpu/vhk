# ADR-013: RULES.md 규칙과 실행 검사의 명시적 연결

> 상태: **Accepted — 2026-08-05 구현 계획 승인.**

## 한 줄 결정

`RULES.md`의 규칙 줄에 `<!-- vhk:check=<id> -->`를 붙여
`scripts/check-rule-<id>.mjs` 또는 `.sh`와 연결하고, `vhk check`가 이를 실행한다.

## 맥락

기존 `vhk check`는 문장 모양으로 추론할 수 있는 일부 규칙만 검사했다. 어떤 규칙이 실제 검사와
연결됐는지 사람이 알기 어렵고, 새 검사 로직을 추가하려면 본체의 문장 해석기를 바꿔야 했다.

## 결정

- 검사는 같은 줄의 HTML 주석 `<!-- vhk:check=<id> -->`로 연결한다.
- ID는 영문 소문자, 숫자, 하이픈만 허용한다.
- 검사 파일은 `.mjs`를 먼저 찾고 `.sh`를 보조로 사용한다.
- 표시가 잘못됐거나 파일이 없거나 검사가 실패하면 `vhk check`도 실패한다.
- RULES.md의 최상위 글머리표 하나를 규칙 선언 하나로 센다.
- 기존 자동 해석 검사와 연결 검사가 같은 줄에 있으면 검사 비율에서는 한 번만 센다.
- JSON과 검사 기록에 선언 수, 검사 수, 미검사 수, 검사 비율을 덧붙인다. 기록 필드는 선택값으로
  두어 이전 JSONL 기록을 계속 읽는다.
- 기존 명령, 옵션, MCP 호출 형식은 바꾸지 않는다.

## 결과

규칙을 읽는 사람은 문서에서 검사 연결 여부를 바로 확인할 수 있고, 프로젝트별 검사를 VHK 본체와
분리해 추가할 수 있다. 반면 표시가 붙은 규칙은 검사 파일을 함께 유지해야 하며, 연결되지 않은 규칙은
`선언만(미검사)`으로 남는다. 검사 비율은 자동화 범위를 보여 줄 뿐 규칙 전체 준수를 보장하지 않는다.

## 고려한 대안

- 파일 이름만으로 규칙을 자동 연결하면 간단하지만 어느 문장을 검사하는지 문서에서 알 수 없다.
- YAML 레지스트리는 구조적이지만 RULES.md와 별도 원본이 생긴다.
- 모든 규칙을 본체의 자연어 해석으로 처리하면 프로젝트별 검사 확장이 어렵고 잘못된 추론 위험이 커진다.
