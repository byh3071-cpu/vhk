# ADR-011: 용어를 업계 통용어로 전면 교체한다

## 맥락 (Context)

VHK 문서·CLI 출력에는 프로젝트 안에서만 통하는 조어가 누적돼 있다. "거짓완료", "기계증거 영수증", "감사층", "자문형/강제형", "승급 다이얼", "트립와이어" 등이다.

세 가지 문제가 있다.

1. **외부에 안 통한다.** 2.x 계열 종료 후 블로그·긱뉴스·Show HN 3채널 게시가 예정돼 있는데, 조어는 첫 문장에서 독자를 잃는다. 같은 개념에 이미 업계 통용어가 있는 경우가 대부분이다(advisory/blocking, config drift, circuit breaker).
2. **내부에서도 의미가 흔들린다.** `vhk gate`(아이디어 검증 인터뷰)와 "게이트"(검증 통과 기준)가 이름만 같고 다른 것을 가리킨다. "감사층"은 `vhk audit`(npm audit 래핑)과 혼동된다.
3. **정체성 문구가 근거를 앞선다.** ADR-006이 정체성을 "거짓완료 탐지기"로 확정했으나, RFC 0056의 성공 기준인 "적발 1건 공개 입증"은 아직 0건이다. 증거가 없는 단정형 명칭을 계속 쓰면 외부 발표 시 방어할 수 없다.

## 결정 (Decision)

**아래 대응표대로 문서·CLI 출력의 용어를 전면 교체한다. 내부 문서(ADR·RFC·goal 카드)도 포함한다.**

| 종전 | 이후 | 비고 |
|---|---|---|
| 거짓완료 탐지 | **완료 보고 검증** | 풀어쓰면 "AI가 '다 했다'고 한 것을 테스트·빌드 결과로 대조" |
| 기계증거 영수증 / Evidence Receipt | **검증 리포트** | 명령명 `vhk receipt`는 유지 |
| 감사층 | **검증 계층** | `vhk audit`(npm audit)과 구분 |
| 자문형 / 강제형 | **경고만 / 빌드 실패 처리** | 업계 advisory vs blocking |
| 규칙 집행 파이프 | **규칙을 문서가 아니라 검사로** | |
| 승급 다이얼 | **권한 단계** | |
| 티어 레인 | **위험도별 승인 규칙** | |
| 트립와이어 | **중단 기준** | |
| 킬게이트 | **중단 판정 기준** | |
| 드리프트 | **설정 불일치(drift)** | 영문 병기 유지 — 검색성 |
| 서킷브레이커 | 그대로 | 이미 업계 통용어 |
| 의도 장갑 | (폐기) | ADR-006 정정노트의 비유. 대체 없이 삭제하고 "의도 대조"로 서술 |

### 불변 (교체하지 않는 것)

**명령명·플래그·설정 키·파일명·JSON 필드명은 바꾸지 않는다.** `vhk receipt`, `vhk verify`, `vhk gate`, `.vhk/ledger.jsonl`, `autonomy-run.jsonl` 전부 그대로다. GA 안정성 약속(ARCHITECTURE.md)이 명령어 이름과 `.vhk` 포맷의 breaking change를 금지하며, 용어 정비는 그 약속을 깨뜨릴 만한 사유가 아니다.

### ADR·RFC 처리 원칙

ADR은 append-only다. **기존 ADR·RFC 본문을 고치지 않는다.** 대신:

- 이 ADR이 용어 대응표의 원본이 된다.
- 종전 용어를 쓰는 ADR·RFC에는 상단에 포인터 1줄만 붙인다: `> 용어: ADR-011 대응표 참조.`
- ADR-006의 정체성 서술은 이 ADR §"정체성 문구"로 갱신한다(ADR-006 본문은 그대로 둔다).

### 정체성 문구

ADR-006이 확정한 결정(1차 타깃·90일 성공 기준·`vhk receipt` 쐐기)은 **유지한다.** 명칭만 바꾼다.

- 종전: "멀티툴 솔로용 무설정 거짓완료 탐지기"
- 이후: **"AI 코딩 결과를 테스트·빌드 결과로 대조하는 1인 개발자용 검증 도구"**

"탐지기"라는 단정형을 뺀 이유는 §맥락 3이다. 적발 사례가 쌓이면 그때 단정형으로 되돌릴 수 있다 — 그건 별도 ADR로 판단한다.

## 대안 (Alternatives)

| 안 | 내용 | 기각 사유 |
|---|---|---|
| A | 외부 문서(README·블로그)만 교체 | 내부·외부 용어가 갈려서 에이전트가 문서를 읽을 때마다 두 어휘를 오간다. 실제로 CLI 출력이 내부 어휘를 쓰므로 "외부만"이 성립하지 않는다 |
| B | 현행 유지 | 게시 시점에 첫 문장에서 독자를 잃는다. §맥락 3의 근거 없는 단정형 문제도 남는다 |
| **C** | **전면 교체 (채택)** | 이력이 두 어휘로 갈리는 비용이 있으나, 대응표 1장 + 포인터 1줄로 흡수 가능하다 |

## 결과 (Consequences)

**긍정**

- 외부 발표 문구가 코드로 증명 가능한 주장만 담게 된다.
- `vhk gate` ↔ 검증 기준, `vhk audit` ↔ 검증 계층의 이름 충돌이 해소된다.
- 신규 사용자가 README에서 만나는 단어가 자기 개발 환경에서 이미 쓰는 단어가 된다.

**부정 / 비용**

- 과거 ADR·RFC와 신규 문서의 어휘가 섞인다. 전문 검색 시 두 단어를 다 쳐야 한다. → 대응표(이 문서)가 그 대조를 담당한다.
- 교체 작업량: `README.md`·`README.en.md`·`VISION.md`·`docs/PRD.md`·`src/i18n/ko.ts`.

**회귀 방지**

- `scripts/check-terminology.mjs`를 신설해 외부 문서와 `ko.ts`에 종전 용어가 남아 있으면 실패시킨다.
- 대상은 외부 표면만이다. ADR·RFC는 append-only라 검사 대상에서 제외한다.

**관련**

- 실행 단위: goal 114 (2.x 로드맵 R0).
- ADR-006(정체성)·RFC 0056(검증 리포트 전략)의 결정 내용은 불변, 명칭만 이 ADR을 따른다.
