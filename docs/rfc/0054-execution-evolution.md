# RFC 0054 — VHK 자율형 진화 로드맵 (Autonomy Evolution)

> 상태: Draft · 작성: 2026-06-20 · 출처: SEO 실제출 논의 → VHK 최종 목적지 논의
> 목적: VHK의 **최종 목적지(자율형)**와 거기 도달하는 **단계적 경로**를 박고,
>       "외부 실제 행동(제출·발송·결제)을 언제·어떻게 열 것인가"에 답한다.
>       부수적으로 SEO goal 22~26의 "무인범위 완료" 정의를 명문화한다.
> 연동: 자문형 헌법(CLAUDE.md "발송·결제·삭제 0") · RFC 0052(자문형 풀사이클) · vhk-auto(자율 1단계) · SOUL 북극성/가드레일.

---

## §1. 배경 — 두 질문

SEO goal 22~26 무인범위 완료 시점에서 두 질문이 떠올랐다:
1. "VHK는 풀사이클 하네스인데, SEO를 실제로 구글/빙에 제출(외부 쓰기)까지 해야 하나?"
2. "VHK의 최종 목적지는 스스로 풀사이클을 돌리는 자율형 운영 아닌가?"

답: **최종 목적지는 자율형이 맞다.** 단 거기 가는 경로에 순서와 안전장치가 있다. 이 RFC가 그 로드맵이다.

## §2. 최종 목적지 — 자율형, 그리고 (세) 축

VHK의 최종 목적지는 **자율형**이다 — 스스로 판단·구동·개선하며 풀사이클을 돌리는 소규모 운영을 지향한다.

단 "자율형"은 단일 스위치가 아니라 **독립된 세 축**의 함수다:

| 축 | 정의 | VHK 현재 | 최종 |
|----|------|----------|------|
| **자율성** | 사람 지시 없이 스스로 한 바퀴 | `vhk-auto` 1단계 MVP | 완전 자율 구동 |
| **진화** | 스스로 규칙·패턴 학습·개선 | `evolve`·`memory`·`pattern` | 자기진화 루프 |
| **실행력** | 외부에 실제 행동(제출·발송·결제) | **0 (자문형)** | 신중·단계적·안전장치 하 |

**핵심: 자율성과 실행력은 다른 축이다.** 둘을 동시에 풀면 = 검증 안 된 자율 AI가 외부에 마음대로 행동 = SOUL 가드레일("확인 없이 배포·삭제·대금 금지", "자동화는 kill switch·rate limit") 정면 위반 = 통제불능 위험.

**비유:** 자율성 = "스스로 운전하는 능력", 실행력 = "차를 실제 출발시키는 권한". 검증 안 된 자율주행차에 출발 권한까지 주면 사고다. 자율주행 능력을 충분히 검증한 뒤, 주차장(저위험)부터 점점 도로로.

## §3. 풀사이클 ≠ 실행형 (현 단계 정합성)

VHK 소스에 외부 HTTP 호출이 **0개**다(2026-06-20 확인). VHK 풀사이클은 전부 "자문형":

| 트랙 | 다루는 것 | 외부 실행 |
|------|----------|:---:|
| content/launch/ops/sell | 상태수집·프롬프트·체크리스트 | ✗ |
| seo | 키·페이로드·가드 준비 | ✗ |

→ 현 단계에서 SEO만 실제출하면 **나머지 트랙과 어긋난다(실행력 축의 불균형 진입)**. 실행력은 전 트랙이 함께, 자율성 신뢰가 쌓인 뒤 열어야 한다.

## §4. 경로 원칙 — 자율성·진화 먼저, 실행력은 단계적

1. **자율성·진화를 먼저 키운다** — `vhk-auto`(자문형 자율: 스스로 돌되 외부실행 0)를 고도화해 "AI가 믿을 만하게 한 바퀴 도는가"를 검증·축적.
2. **신뢰가 쌓인 뒤 실행력을 단계적으로** — 저위험(자기 사이트 색인)부터 → 고위험(발송·결제). 각 단계 opt-in·dry-run·kill switch·확인 게이트.
3. **자문형은 종착지가 아니라 "실행력 0" 출발점.** 자율성·진화 축은 이미 전진 중이다.

## §5. 결정

- **D0 — 최종 목적지는 자율형, 경로는 단계적.** VHK는 자율 실행형으로 진화한다(북극성 부합). 단 자율성·진화 먼저, 실행력은 신뢰 축적 후 단계적(안전장치 하).
- **D1 — 현 단계 기본값은 자문형(실행력 0).** 무인범위(상태수집·준비·가드·프롬프트)까지가 현재 VHK 책임. 자율성·진화 축은 계속 전진.
- **D2 — 실 외부 실행은 "실행력 단계"로 통째 이관.** SEO 제출/발송/결제를 개별 goal에서 슬쩍 시작하지 않는다. §6 트리거 충족 시 전 트랙 함께 설계.
- **D3 — SEO goal 22~26은 "무인범위 완료"로 정의.** check-goal 게이트가 완료 SoT. 실 API는 D2로 이관. (§7)

## §6. 실행력을 여는 트리거 — 언제 D2를 발동하나

다음이 충족될 때만 실행력 단계 검토:
- **자율성 신뢰 축적** — `vhk-auto`가 사람 개입 없이 안정적으로 한 바퀴 도는 게 측정으로 입증.
- **실 병목 확인** — 수동 실행(제출·발송)이 실제 병목임이 측정됨(다수 사이트·높은 빈도 등).
- **명시적 비전 확정** — 오너가 "이 트랙을 실행형으로"를 명시 결정.
- 그 전까지: 자문형 유지. SEO 실제 제출은 사용자가 웹UI에서 직접(평생 몇 회).

## §7. SEO goal 22~26 — 무인범위 완료 정의

각 goal은 check-goal-N 게이트 통과 = 완료(2026-06-20 정적 ✓, deep은 CI green):

| goal | 무인범위(완료) | 실 API(D2 이관) |
|------|---------------|----------------|
| 22 submit | IndexNow 키·페이로드·구글금지 가드 | GSC/Bing 제출·IndexNow 핑 |
| 23 check-index | URL Inspection 한도가드·스키마 | GSC·GA4 수집 |
| 24 check-revenue | v1.4 금지가드·딥링크 폴백 | AdSense·Bing 수집 |
| 25 report | latest.json→HTML 렌더·딥링크 | (23·24 실수집 후) |
| 26 automate | 스케줄러·확장슬롯 IF | Notion 실적재 |

→ goal 카드 Completion Check의 "실 수집/제출" 항목은 D2로 이관됨을 명시. 무인범위 게이트 통과로 DONE 처리.

## §8. 실행력 단계 설계 원칙 (미래 참조 — 지금 구현 안 함)

D2 발동 시 SEO 하나가 아니라 **전 트랙을 통째로** 다음 원칙으로 설계한다:
- **opt-in 기본 off** · **dry-run 우선** · **kill switch + rate limit** · **확인 게이트**(되돌릴 수 없는 행동 전, 비대화형은 차단)
- **시크릿 안전**(`.env` 참조, 평문 로그 0) · **감사 로그**(agent-action-ledger, goal 55) · **HTTP 레이어 단일화**(fetch 래퍼 SoT + 목업 테스트)

## §9. 범위 밖 (지금 안 함)
- 실 외부 API 구현 · HTTP 클라이언트 도입 — D2 이관, 미착수.

## §Overnight — 무인 goal → PR 래퍼 (머지 0)

야간 자율 루프가 **commit만** 하는 vhk-auto(INV-7)와 **push+PR만** 하는 overnight 래퍼의
경계를 분리한다. 머지는 사람만. 상세·하드 게이트·HARD_STOP 계약은
**[RFC 0063](./0063-overnight-vhk-auto.md)** (Draft)와
`docs/runbooks/overnight-vhk-auto.md` 를 SoT로 둔다.

- overnight-autoloop(mcp/관제탑 결함 루프)와 **혼용 금지**.
- 2단계 CLI `vhk auto` 는 여전히 OUT(§6 D2 트리거 전).
