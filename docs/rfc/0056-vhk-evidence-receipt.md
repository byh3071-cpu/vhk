# RFC 0056 — VHK Evidence Receipt: 에이전트의 '됐어요'를 영수증으로

> 용어: ADR-011 대응표 참조.

> 상태: Draft · 작성: 2026-06-22 · 출처: RFC 0055 다차원 검증(§13) + `vhk-winning-strategy` 전략 workflow(6후보 4렌즈 적대평가)
> 대체: **RFC 0055 §8(표준화 전략)·§7(역할군) 프레임을 폐기하고 이 RFC로 교체.** RFC 0055의 객체모델·티켓(§3·§4·§9)은 결함 정정 후 재사용.
> 연동: RFC 0052(풀사이클 뒷단) · RFC 0054(자율형 진화) · ADR-006(정체성 확정) · `verify/review/mission/work` · `.vhk/reports/latest.json` · `verify.ts`(verifyEvidence·checkEvidenceFreshness).

---

## §0. 핵심 정리

RFC 0055는 "VHK Proof Protocol = AI 작업 신뢰 원장 → Public 표준"을 제안했다. 다차원 검증(0055 §13)에서 토대 두 곳이 무너졌다:

1. **순서 역전** — 표준화는 "이미 채택된 것을 고정"인데 채택 0·구현 0·검증기 단일종속 상태에서 표준을 선언했다.
2. **과대약속** — 기반 `vhk review`조차 "보장 아닌 신뢰도 신호"라 자인하는데 'Proof(증명)'·"No proof, no ship"으로 격상했다.

이 RFC는 같은 자산(거짓완료 검증)을 **정직하게 좁혀** 이길 수 있는 단일 포지션으로 재정의한다.

**정체성 한 문장:**

> **VHK는 "AI가 '됐어요'라고 말한 순간, 종료코드·dirty·SHA 같은 기계증거만으로(LLM 판단 0) 그 말이 진짜인지 1초에 따지는, 멀티툴 솔로용 무설정 거짓완료 탐지기다."**

**슬로건:**

> **에이전트의 '됐어요'를 영수증으로 바꾼다 (Turn "it's done" into a receipt).**

**제품명:** `Proof`(증명)가 아니라 **Evidence Receipt(증거 영수증)** — 영수증은 "이런 일이 일어났다는 기록"이지 "이게 옳다는 보증"이 아니다. 톤이 능력과 일치한다.

## §1. 왜 재정의하나 (0055 교체 근거)

전략 workflow가 6개 후보(증거영수증·납품증명서·출고검문소·휴대용두뇌·블랙박스·관제탑)를 4렌즈(해자·실행·수요·정합)로 적대평가했다. 결과 점수(투명성 위해 §10에 전체 기록):

| 순위 | 후보 | 평균/10 | kill |
|------|------|---------|------|
| 1 | 증거 영수증 (채택) | 5.3 | 1 |
| 2 | 납품 증명서 | 5.3 | 1 |
| 3 | 출고검문소 | 5.0 | 2 |
| 4 | 휴대용 두뇌 | 4.5 | 3 |
| 5 | 블랙박스 | 4.0 | 3 |
| 6 | 관제탑(무인머지) | 3.8 | 3 |

> ⚠️ **정직한 경고:** 승자조차 5.3/10이다. 이건 "이김 보장"이 아니라 "6개 중 최선 + 결함을 정직하게 흡수한 안"이다. 본질적으로 니치이며, §8 킬 조건으로 빠르게 검증·폐기할 각오가 전제다.

채택 이유: 1위만 kill이 사실상 최소(다른 후보는 수요/해자에서 kill 2~3)이고, **정직성 자체가 자산**이다 — 0055 검증 결함(과대약속·위조 위협모델·중립성 자기모순)을 회피가 아니라 정면 흡수해 'Proof'→'Evidence'로 격하했다.

## §2. 정체성·포지셔닝

VHK가 파는 것은 "코드 생성"도 "더 똑똑한 리뷰"도 아니다. **"AI 자기보고를 기계증거로 대조해 거짓완료를 잡는 결정론 판정"**이다.

소유할 헤드라인:

> **"AI가 '됐어요'라고 할 때, 진짜 됐는지 기계가 1초에 따진다."**

산출물(.md) 하단 고정 1줄(정직성을 제품에 박음):

> *"이 판정은 기계증거(종료코드·dirty·SHA) 기반이며 LLM 추론이 아니다. 통과해도 미묘한 오류는 남을 수 있다."*

## §3. 1차 타겟

**추천 1차 타겟: 세그먼트 B — 멀티툴 CLI 에이전트 헤비유저** (Claude Code·Codex·Cursor·Cline·Aider를 주 2~3개 번갈아 쓰는 솔로/2~3인).

근거 4축:

- **고통**: 거짓완료를 이미 자기 언어로 아파한다("에이전트가 훅 고쳤다 우기는데 코드 안 바뀜 = vibe killer"). 검증갭·신뢰도 데이터로도 뒷받침.
- **지불의사**: 이미 월 구독 도구에 복수 결제 중 → 결제 장벽 낮음.
- **접근성**: 1인 비개발 오너가 닿는 채널(GitHub·X·HN·각 도구 Discord)에 모여 있고, "자기보고 신뢰 대신 기계증거 대조"를 설명 0으로 이해한다.
- **★1인 도그푸딩 가능성★**: 이 타겟의 성공 측정은 사람-대화형 라벨링(Recall@5)이 **아니라** "기계증거가 거짓완료를 block한 장면 1건"이다. verify는 실행만 하면 `.vhk/reports`가 비대화형 누적 → measure-first의 사람 율속 병목을 이 타겟에서만 우회한다.

확장·회피:
- **세그먼트 C(납품 프리랜서·스튜디오) = 2순위 확장축.** 지불의사·고통 최상이나 도달 난이도 최상 + 양면시장(발급자↔수령자) 콜드스타트. 90일엔 안 건드리고, B에서 영수증 작동 입증 후 "납품물 첨부"로 진입.
- **세그먼트 A(바이브코더)** = 교육비용 큼, **D(AI PR 많은 팀)** = CodeRabbit 선점 → 둘 다 회피.

## §4. 해자 (이기는 비대칭 · 정직하게 강약)

**핵심 축:** *"멀티툴을 갈아타는 솔로의 통합 영수증은 단일 벤더가 만들 인센티브가 구조적으로 없다."*

- **(강) 음성 해자 — 벤더 이해상충.** Claude Code·Codex·Cursor의 사업모델은 락인. "경쟁사 에이전트 작업까지 의심하는 외부 영수증"을 만들 동기가 0(자기 제품 신뢰 깎기 + 이탈 조장). VHK는 무소속이라 중립을 팔 수 있는 유일 위치. 단 "제품 해자"가 아니라 "경쟁자 동기 부재"라 좁은 세그먼트에서만 실재.
- **(중) 결정론 vs 확률.** 리뷰봇(BugBot·Copilot review·Claude /review)은 LLM이 코드 읽고 확률 판단 → 그 자체가 할루시네이션 가능. VHK는 dirty/stale/exit≠0이면 기계가 block, **caution→pass 격상 금지가 코드 불변식**. 검증기 자신이 거짓말 안 하는 속성은 LLM 리뷰봇이 구조적으로 못 가짐. (단 GitHub Actions도 결정적이라 절반 겹침 — 차별점은 "CI 통과여부가 아니라 자기보고 위조 방어".)
- **(약·정직) 자기보고 위조방어.** typecheck/test/build 필드는 `manual:true` 자기보고를 거부하고 외부프로세스 실종료코드만 기록(verify.ts 이미 그럼). 단 decision을 내리는 3개 기계사실(exit·dirty·SHA)에만 강하고, 휴리스틱 필드(impliedGates·goal 체크박스)는 약함 → 마케팅에서 뭉뚱그리면 자기모순.

**못 버티는 약점(정직):**
- 복제 1~2주. `git status --porcelain` + 종료코드 + SHA 비교는 주말 프로젝트. 동종 오픈소스 이미 존재 → 해자는 코드가 아니라 **선점 속도 + 도그푸딩 신뢰자산 + 무방비 세그먼트**.
- 검증기 vhk CLI 단일종속 → "표준" 금지, "이식 가능한 자기규율 도구"로만 주장.
- 단일벤더가 안 만드는 자리 = 시장도 작을 수 있다(니치 함정) → §8 킬 조건 #2로 검증.

## §5. 경쟁 프레임 (안 겹치는 자리)

| 경쟁자 | 그들의 프레임 | VHK 프레임 |
|--------|---------------|------------|
| CodeRabbit / Greptile | 제3자가 **남의** PR 게이트키핑 | 솔로가 **자기** 에이전트 거짓완료 자가검증 |
| Claude /review · BugBot | LLM이 코드를 **읽고 판단**(확률) | 기계가 종료코드를 **세고 차단**(결정론) |
| GitHub branch protection | CI가 **통과했나** | 에이전트 자기보고가 **위조됐나** |
| Qodo · Sonar(엔터프라이즈) | 플랫폼팀·SSO·감사 | 무설정·솔로·repo 1개 |

## §6. 90일 첫 쐐기 — 명령 하나 `vhk receipt`

어느 에이전트가 "완료"라 말하든, 그 순간:
- ① tsc/test/build 실종료코드 ② git dirty ③ stale(작업시작 SHA ≠ 현재 HEAD) ④ 변경라인 diff-cover

를 수집해 `.vhk/receipts/<날짜-슬러그>.{json,md}` 영수증 1장으로 굳히고, 기계증거가 모순이면(dirty/stale/red) **decision=block을 LLM 판단 0으로** 낸다.

> **정직 경계(2026-06-23 적대검증 반영 · §11):** ④ diff-cover는 advisory 약신호다 — "테스트 실행 도달"이지 "정확성"이 아니라, 그럴듯하게 틀린 코드(assertion 0·틀린 assert)는 구조적으로 못 잡는다(`diff-coverage.ts:42`·`diff-cover.ts:69`). 따라서 receipt가 실제로 잡는 것은 **"게으른 거짓완료"(빌드 깨짐·미커밋·stale)에 한정**되며, 이는 정밀화로 넓혀지지 않는다(한계가 정밀도가 아니라 "커버리지=실행도달" 정의). 그러므로 4대 증거를 "거짓완료를 전부 잡는다"로 팔지 않고, 산출물 .md 정직성 1줄에 경계를 박는다 — *"이 영수증은 게으른 거짓완료를 잡지, 미묘한 오류는 못 잡는다."*

**기존 자산 재사용(신규 발명 금지):** `verifyEvidence`(실종료코드)·`review`(거짓완료 교차검증)·`checkEvidenceFreshness`(stale 강등)·evidence-ledger·`reports/latest.json` 병합 — 이미 디스크 작동. receipt는 이들을 1장으로 조립하는 글루코드.

**90일 밖(제외):** 표준화·proof 6객체·CI status check·외부발송·무인 머지·history replay·다타겟 sync 전부.

### 첫 3티켓

**T1 — `vhk receipt` MVP (1 goal = 1 PR).**
완료 시점 4대 기계증거 수집 → `.vhk/receipts/<날짜-슬러그>.{json,md}` 생성. decision=block|caution|pass는 기계증거로만(LLM 0), dirty/stale/red면 무조건 block, **caution→pass 격상 금지 단조성 불변식을 테스트로 고정**.
- ★수용기준★: 등록 4지점(index·command-registry·cli-args·ko.ts) + nlp-router + 한글별칭(`증거영수증`) + 드리프트테스트 green 명시 — RFC 0055 §13-high#3(등록 누락 시 첫 게이트서 빌드 깸) 정면 예방.
- ★선결★: #315(verify가 ledger.jsonl 갱신 → 거짓 dirty → 늘 block) 봉인 — 안 고치면 데모 첫 장면에서 영수증이 늘 빨강이라 자기모순.

**T2 — 자기보고 위조방어 코드화 + 붙여넣기 .md.**
typecheck/test/build 필드는 `manual:true`/self-report 입력을 **소스 assertion으로 거부**, 외부프로세스 실종료코드 출처만 허용. 사람용 .md는 PR/대화에 그대로 붙는 1블록(decision 배지 + 게이트표 + dirty/stale 사유 + 정직성 경계 1줄). `.vhk/receipts/`는 git 추적 여부를 "추적 + 민감정보 마스킹"으로 결론 + gitignore·init 씨앗 동반(#331 gitignore 누락 재발 방지).

**T3 — 거짓완료 적발 1건 공개입증 (사람 율속, measure-first).**
토이/실작업에서 에이전트가 "완료"라 주장했으나 기계증거가 block을 낸 케이스를 며칠 실사용으로 **1건 이상 캡처**(현재 차단율 0/8 → 최소 1건). 합성·소급 금지. 적발 장면(에이전트 done 발화 → 영수증 block → 실제 미완 확인)을 docs/log에 증거기반 기록 = 향후 랜딩/트윗 단일 데모 자산. **효과 0이면 가설 폐기·각도 전환을 정직하게 결정(§8).**

## §7. RFC 0055 §8/§7 교체 명세

- **§8 "표준화(VHK Proof v1 public spec)" → "도그푸딩 효과입증 → 채택 관찰" 2단으로 교체.** 표준은 채택자가 생긴 뒤 따라오는 후행지표지, 채택 0·구현 0·검증기 단일종속에서 선언하는 선행 목표가 아니다. 6개월 목표를 "Proof v1 스펙 공개"에서 → **"자기 레포 거짓완료 적발 N건 공개 + 외부 3~5명이 영수증을 실제 워크플로에 켰다는 관찰 1건"**으로. 표준화는 그 다음.
- **§7 "6개 인간 역할 팀" → "소규모 오너 + AI 에이전트 + 1 goal=1 PR 케이던스".** 6인 팀 전제는 실제 운영과 모순되어 기각했다. 프로젝트 관리자는 방향·기획·검수·최종결정을, 에이전트는 구현·테스트·문서·sync를 맡는다. 인간 팀이 채울 거버넌스·리뷰·집행은 결정론 게이트·runGuarded chokepoint·HARD_STOP이 대신한다. **"표준은 사람을 모아야 한다" → "규율은 코드로 박는다."**

## §8. 킬 조건 + 성공기준

하나라도 충족되면 정직하게 멈추고 재논의한다:

1. **[90일 단일 성공기준 / 1차 킬] 거짓완료 적발 0건.** T3에서 며칠 실사용해도 "에이전트가 done이라 했는데 기계증거가 실제 미완을 잡은" 장면이 1건도 안 나오면 → 핵심 명제가 자기 레포서도 거짓, 즉시 폐기. (현재 0/8이 출발선.)
2. **[최치명 / 니치 함정] 외부 사용자 0.** 6개월에 GitHub star·외부 사용 신호가 사실상 0(현 star 1·fork 0)이고 영수증을 켠 외부인 0명이면 → 세그먼트 C로 피벗하거나 접는다.
3. **[해자 증발] 벤더 내장.** Claude Code가 "멀티툴 통합 영수증"을 1급 기능으로 내장하면 → 중립성 해자 증발, 피벗.
4. **[늘 빨강/늘 초록] 효과 무의미.** 영수증이 stale/dirty만 잡고 "almost right but not quite"(미묘하게 틀린 코드)는 구조적으로 못 잡아 신호등이 항상 한 색이면 → verify 존재이유 붕괴(#315가 '늘 빨강' 실증). diff-cover 정밀화로 6개월 내 못 고치면 가치명제 폐기.
5. **[지불의사] 솔로가 무료/내장으로 때움.** 세그먼트 B 인터뷰 5~10명에서 "무료 대안/내장 hooks 대신 이걸 쓸 트리거"가 하나도 안 나오면 → 솔로 과금 가설 폐기, 세그먼트 C 단독 재설계.

> 가장 빨리 답 나오는 #1을 **90일 단일 성공기준**으로. 통과하면 #2·#5를 6개월 기준으로 검증.
