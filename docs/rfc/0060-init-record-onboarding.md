# RFC 0060 — init 기록 온보딩: 채움 마커·인터뷰 2단계·자동 sync·설치 점검

> 용어: ADR-011 대응표 참조.

> 상태: Draft · 작성: 2026-07-12 · 출처: 사용자 니즈("독푸딩 시 PRD·아키텍처·ADR·트러블슈팅을 새로 만들 필요 없이, 초기 설명 비용을 0으로 — 기록을 짚어주지 않아도 되게") + `/dogfood` 감사(2026-07-12) Wave 1 후속
> 목적: `vhk init` 한 번으로 **기록 인프라가 사용자 개입 없이 완비**되게 한다. 사람이 "여기 뭘 채우지"를 헤매지 않고, AI가 사용자 의도를 인터뷰로 뽑아 기획 문서를 채우며, 배선 완료를 **거짓 없이 영수증으로 증명**한다.
> 연동: `src/commands/init.ts` · `src/i18n/ko.ts` · `src/templates/{prd,architecture,customization-hook}.ts` · `src/commands/sync.ts` · RFC 0057 §7(트리거 격차 계승) · RFC 0056(거짓완료 영수증 철학)

---

## §0. 한 줄 결론

기록 문서 골격은 이미 배출된다(Wave 1 확인 — 26파일 정상). 남은 3구멍은 **① 채울 자리가 어딘지 사람이 모름**(마커 부재), **② AI가 의도를 뽑아 기획문서를 채우는 흐름이 없음**(첫 세션 인터뷰가 도메인 규칙 4문항 전용), **③ 배선이 됐다는 걸 믿을 근거가 없음**(sync 수동·검증 없음). 이 셋을 **관행 마커 + 인터뷰 2단계 + 자동 sync + 설치 점검 영수증**으로 닫는다. 강제 창작은 하지 않는다 — AI는 인터뷰로 뽑은 사용자 답변만 받아쓰고, 못 채운 칸은 마커로 남겨 가시화한다.

---

## §1. 동기 (실측 — Wave 1 감사)

- **채움 마커 부재**: init 완료 안내가 "채우세요"라 하나 생성 파일 어디에도 채울 위치 표식이 없었다(Wave 1에서 죽은 안내문은 정직화했으나, 근본 = **채울 자리 자체가 안 보임**은 미해결).
- **인터뷰 범위 협소**: goal 89 커스터마이징 훅(`customization-hook.ts`)은 **도메인 규칙 4문항**(핵심 규칙·금지 행동·외부 API·데이터 민감도)만 뽑아 `RULES.md`에 적재. PRD·ARCHITECTURE는 손대지 않음 → 사용자가 "기획/설계 초반에 몰입해서 써야 할 것"을 여전히 혼자 백지에서 시작.
- **sync 수동**: `vhk init` 후 `AGENTS.md`가 없다(sync가 만듦). init next-steps에도 sync 안내 없음 → Codex·Zed 등 `AGENTS.md` 인식 에이전트가 규칙(기록 규칙 포함) 없이 시작.
- **배선 불투명**: init이 20여 파일·훅·mission을 만들지만 "다 됐는지" 확인할 요약이 없음 → 사용자는 "한방"을 **믿어야만** 함(검증 불가).

## §2. 원칙

| 관점 | 적용 |
|------|------|
| **관행 우선 (실무 언어)** | 채움 마커는 개발자 은어(`__FILL__`) 금지 → 계약서·회사 양식의 `[여기에 작성: 질문]` 관행. 일반인·사무직·개발자가 공유하는 표기. ASCII·검색가능·AI 기계파싱 가능. |
| **받아쓰기 ≠ 창작 (헌법: LLM은 결정경로 밖)** | AI는 기획 문서를 **지어내지 않는다**. 인터뷰로 뽑은 사용자 답변만 슬롯에 채우고, 답 못 얻은 칸은 마커로 남긴다. PRD/ARCHITECTURE 상단에 "이 칸은 대화로 채움 — AI 추측 금지" 가드 한 줄. |
| **불가침 문서 존중** | `VISION.md`는 인터뷰 대상 제외 — 사용자가 직접 쓰는 정체성 문서(vhk 본체 관례 동일). AI가 채우면 안 됨. |
| **비대화 취조 방지** | 첫 세션 인터뷰는 도메인(4문항)과 기획(PRD 슬롯)을 **분리**하고, PRD 슬롯은 5±2개 상한 + "지금 채울래 / 개발하며 채울래" 선택. 15문항 취조로 초보를 쫓지 않는다. |
| **거짓완료 금지 (RFC 0056)** | 자동 sync 후 **파일 실재+마커를 다시 읽어** 검증한 "설치 점검" 영수증만 출력. "썼다"고 믿지 않고 읽어서 확인. 실패는 ❌+복구 명령으로 정직 표기. |
| **브라운필드 안전** | 자동 sync는 기존 파일을 덮을 수 있음 → **그린필드 + adopt 승인**한 경우만 자동 실행. adopt 거절 시 안내만. |

## §3. 트랙 (작은 단위)

### T1 — 채움 마커 `[여기에 작성: 질문]`
- 대상: `docs/PRD.md`·`docs/ARCHITECTURE.md`(기획/설계 = 몰입 대상). ADR·트러블슈팅·log·til·patterns는 마커 불필요(수시 기록, 골격+규칙 이미 배출·놓침 방지는 RFC 0061 담당).
- `prd.ts`·`architecture.ts` 템플릿의 빈 섹션을 `[여기에 작성: 구체 질문]`으로. 예: `## 타겟 사용자\n[여기에 작성: 누구를 위한 제품? 그 사람은 하루 중 언제 이걸 쓰나?]`
- 문서 상단에 가드 한 줄: `> 이 문서의 [여기에 작성] 칸은 사용자와 대화로 채웁니다 — AI가 추측으로 채우지 않기.`
- `--from-notion` 경로: 노션에서 채워진 필드는 마커 없이, 빈 필드만 마커 유지(부분 채움 정합).

### T2 — 첫 세션 인터뷰 2단계 (customization-hook 확장)
- 기존 1단계(도메인 규칙 4문항 → RULES.md) **뒤에** 2단계 추가:
  - "PRD·ARCHITECTURE의 `[여기에 작성]` 슬롯을 **사용자 답변 기반으로만** 채워라. 알아서 창작 금지. 한 번에 하나씩, PRD 핵심 5±2개만. 채운 뒤 요약 보여주고 컨펌받아라. 사용자가 '개발하며 채울게'라 하면 존중하고 마커를 남겨라."
  - VISION.md는 건드리지 말라 명시.
- `customization-done` 마커 로직은 그대로(재넛지 방지).

### T3 — init 자동 sync + 설치 점검 영수증
- init 마지막에 조건부 sync(in-process): 그린필드 or adopt 승인 시만. adopt 거절/기존 RULES.md 존재 시 안내만.
- sync 후 **읽기 검증**: 6개 규칙 타깃 파일 실재 + 내용 마커 확인 → 영수증 출력.
- 영수증 문구는 실무/가구조립설명서 톤(전문용어 금지):
  ```
  📋 설치 점검 — 다 준비됐는지 확인했어요
    규칙 파일    6개 모두 연결됨 ✅
    기록 폴더    8종 만들어짐 ✅ (결정·에러해결·세션일지…)
    첫 인터뷰    다음 세션 시작 때 자동으로 시작돼요
    남은 일      git init 한 줄만 (아래 복붙)
  ```
- sync 실패해도 init 산출물 보존, 영수증에 ❌ + 복구 명령 1줄.

### T4 — 트리거 격차 계승 (RFC 0057 §7)
- RFC 0057 §7이 "SessionStart 훅은 Claude Code 전용 → 다른 에이전트는 자동 온보딩 못 받음"을 **미해결 설계공백**으로 기록해둠. 0060이 이를 계승해 **도구 무관 백업 트리거**를 T1 마커 자체로 확보:
  - `RULES.md`에 "'[여기에 작성]' 칸이 보이면 사용자와 대화로 채워라(AI 추측 금지)" 한 줄 → `vhk sync`가 CLAUDE.md·AGENTS.md·.cursorrules 전 에이전트 파일로 전파.
  - 효과: Claude Code는 SessionStart 훅으로 능동 트리거, Cursor·Codex는 파일 안 규칙 문구로 수동 트리거 — 어느 에이전트로 열어도 "빈칸 방치"가 안 됨.
- ⚠️ 이건 훅 대체가 아니라 **백업**. 훅 없는 에이전트의 자동성은 여전히 낮음(규칙을 읽고 따를지는 에이전트 품질 의존) — 정직히 "격차 축소"지 "격차 소멸" 아님.

## §4. 성공 기준

- init 후 PRD·ARCHITECTURE에 `[여기에 작성]` 슬롯이 보이고, `vhk check`가 잔여 슬롯 수를 카운트(측정 가능).
- 그린필드 init 후 `AGENTS.md` 즉시 실재(자동 sync) + 설치 점검 영수증이 읽기검증 기반으로 출력.
- 브라운필드(adopt 거절) init이 기존 파일을 **덮지 않음**(회귀 테스트).
- 인터뷰 2단계가 PRD 슬롯을 **사용자 답변으로만** 채우고 VISION.md 무변(라이브 세션 실측).
- **최종 지표(다음 독푸딩)**: 워크플로 계측 DB에서 **기록 관련 수정지시 0회** = "짚어주기 제거" 달성.

## §5. 범위 / 비목표

- **IN**: T1~T4. 마커·인터뷰 2단계·자동sync·영수증·백업 트리거 문구.
- **OUT**:
  - 기록 **집행**(놓친 ADR/TS를 커밋 시점에 잡기) → RFC 0061 소관. 0060은 "채우기 쉽게"까지, 0061은 "안 하면 잡기".
  - Cursor/Codex용 네이티브 훅 메커니즘 신설 → RFC 0057 §8 비목표 유지(근거 조사 선행 필요).
  - README.md 템플릿 init 배출(노션 P0) → 별도 소규모 트랙(0060 성공 후 검토).

## §6. 위험 / 엣지

- **마커 남발로 문서 지저분**: PRD·ARCHITECTURE 한정 + 상단 가드 1줄로 슬롯당 지시문 중복 회피.
- **인터뷰 취조감**: 5±2 상한 + "개발하며 채울래" 옵트아웃. 그래도 길면 사용자 피드백으로 축소.
- **자동 sync가 남의 파일 덮음**: 그린필드/adopt승인 게이트로 원천 차단. sync 자체 백업가드는 2차 방어.
- **백업 트리거 무력**: 저품질 에이전트가 규칙 문구를 무시하면 빈칸 방치 → 격차 "축소"지 "소멸" 아님을 정직 표기(§3 T4).
- **`vhk check` 슬롯 카운트 오탐**: 마커 문자열 정확 매칭(`[여기에 작성:`)으로 오탐 최소화.

## §7. 열린 결정 (구현 전 확정 필요)

1. **인터뷰 2단계를 훅 프롬프트에 넣을지, 별도 스킬로 뺄지** — 훅 프롬프트가 길어지면 SessionStart 부담. [추론] 훅은 "지시"만 하고 실제 인터뷰는 AI 자율이 나을 수 있음. 구현 시 판단.
2. **PRD 슬롯 상한 정확값**(5±2의 실제 개수) — 템플릿 섹션 수에 맞춰 확정.
3. **`vhk check` 슬롯 카운트를 별도 트랙으로 뺄지** — 작으면 T3에 흡수.
