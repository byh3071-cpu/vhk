# RFC 0061 — 기록 집행 3겹 그물: 놓친 ADR·트러블슈팅·세션일지를 사람 개입 없이 잡기

> 상태: Draft · 작성: 2026-07-12 · 출처: 사용자 니즈("기록이 중요한데 그때그때 '아 이거 기록해야 하는데' 하며 내가 계속 짚어 나가지 않게") + `/dogfood` 감사(2026-07-12)
> 목적: 기록 규칙이 **선언은 배출되나 집행이 0**인 구멍을 닫는다. 단, 커밋 훅 하나로 다 잡힌다는 거짓 주장을 하지 않고, **각 겹이 무엇을 잡고 무엇을 흘리는지 정직히** 설계한다.
> 연동: 새 프로젝트 `.git/hooks` 또는 `.vhk/hooks` · vhk 본체 `check-records` hook 패턴 · RFC 0051(handoff 미기록 후보 수확) · `src/lib/doc-suggest.ts`

---

## §0. 한 줄 결론

기록 집행을 **커밋 훅 하나로 해결**하려는 유혹은 틀렸다 — 훅은 기계라 "src 바뀌었는데 오늘 세션일지 없음"은 판별하지만, "이 커밋에 기술 결정이 있으니 ADR 필요"는 **의미 판단**이라 기계가 못 한다. 그래서 **3겹 그물**로 간다: ①규칙 선언(이미 배출) ②커밋 훅(세션일지 누락 100% 차단, 마찰은 사람이 아니라 **AI가 받음**) ③세션종료 수확(ADR/TS 의미 후보 감지 — RFC 0051 이식). 마찰을 AI에게 돌리는 게 핵심 — 바이브코딩에서 커밋 버튼은 AI가 누르므로, "짜증"은 사람이 아니라 에이전트가 흡수한다.

---

## §1. 동기 (실측)

- **선언은 있고 집행은 없다**: 새 프로젝트 `CLAUDE.md`(기록 전용) + `RULES.md §기록 규칙` + Dev Log 적재 규칙이 배출됨(Wave 1 확인). 그러나 강제 장치는 커스터마이징 체크 훅 하나뿐 → **AI가 규칙을 무시하면 결국 사람이 짚어야 함**(사용자 니즈의 마지막 구멍).
- **vhk 본체엔 이미 방어가 있다**: vhk 레포는 `check-records` hook이 "실질 코드변경 커밋 시 세션 dev log 스테이지 필수 — 없으면 커밋 차단"(governance-v2 T1). 이 방어가 **새 프로젝트엔 이식 안 됨**.
- **RFC 0051 수확도 이미 있다**: `vhk work handoff`가 `doc-suggest.detectDocCandidates`로 미기록 ADR/TS 후보를 감지·프롬프트 주입. **전역 명령이라 모든 프로젝트에서 작동** — 단, 새 프로젝트 CLAUDE.md가 "세션 끝낼 때 handoff 실행"을 지시하는지는 미확인(§7 확인 항목).

## §2. 3겹 그물 — 각 겹이 잡는 것 / 흘리는 것 (정직 매트릭스)

| 겹 | 시점 | 잡는 것 | 흘리는 것 | 구현 상태 |
|----|------|---------|-----------|-----------|
| ① 규칙 선언 | 작업 중 실시간 | AI가 성실하면 ADR·TS 즉시 기록 | AI가 깜빡하면 끝 | ✅ 이미 배출 |
| ② 커밋 훅 | 커밋 순간 | **세션일지 누락 100%**(결정적 검사) | ADR·TS는 의미판단이라 불가 | 🔴 신규(이식) |
| ③ 세션종료 수확 | handoff | ①이 흘린 ADR·TS 후보를 diff에서 감지 | handoff 없이 세션 끊기면 | 🟡 존재하나 새프로젝트 배선 확인 필요 |

- **왜 훅만으론 반쪽인가**: ②는 "오늘 날짜 세션일지 파일 존재 여부" 같은 결정적 신호만 검사 가능. "이 diff가 ADR감인가"는 `doc-suggest`가 룰 기반 후보를 낼 수 있으나 **확정은 못 함**(오탐 많아 차단 부적합) → 자문형인 ③으로 흘려보내는 게 맞음.
- **마찰의 귀착점 전환**: ②가 커밋을 멈추면 그 마찰을 받는 건 커밋 실행자 = **AI**. 에러 메시지를 사람용 잔소리가 아니라 **AI용 작업지시서**로 쓰면(→ AI가 그 자리에서 일지 쓰고 재커밋) 사용자는 아무것도 안 봄. 이게 "짚어주기 제거"의 실체.

## §3. 트랙

### T1 — 커밋 훅 이식 (②)
- 새 프로젝트에 pre-commit 훅 배선. **결정적 검사만**: `git diff --cached`에 실질 코드(src/** 등) 변경이 있는데 `docs/log/YYYY-MM-DD-*.md`(오늘 또는 연속세션 어제)가 스테이지에 없으면 차단.
- 에러 메시지 = **AI 작업지시서**: "세션 일지 초안 작성 → 스테이지 → 커밋 재시도. 사소·문서성 커밋이면 커밋 메시지에 `[skip-record]`." (vhk 본체 문구 이식)
- **배선 시점 문제**(§6 위험): `vhk init` 시점엔 `.git`이 없을 수 있음 → 훅을 `.git/hooks`에 직접 심으면 git init 전엔 무효. 해법 후보: (a) init이 git 없으면 훅 대기 마커 남기고 다음 실행 시 배선, (b) `core.hooksPath`를 `.vhk/hooks`로 지정해 git init 후에도 유효. 구현 시 확정.
- **도구 불가지론**: git 훅이라 Claude Code·Cursor·Codex 어디서 커밋해도 작동(Claude 전용 훅으로 만들면 RFC 0057 트리거 격차 재생산 — 회피).

### T2 — 세션종료 수확 배선 확인·강화 (③)
- `vhk work handoff`의 `doc-suggest` 후보 감지는 이미 전역 작동. 새 프로젝트 `CLAUDE.md`/`RULES.md`가 "세션 종료 시 `vhk work handoff` 실행" 의례를 지시하는지 확인 → 없으면 `RULES.md §기록 규칙`에 한 줄 추가(sync 전파).
- 백스톱의 백스톱: handoff 없이 세션이 끊긴 경우 → 다음 세션 SessionStart에서 "어제 기록 공백 감지" 알림. [추론] 과설계 위험 있어 RFC에서 IN/OUT 판단 필요(§5).

### T3 — 규칙 문구 정합 (①)
- `RULES.md §기록 규칙`에 3겹 그물 존재를 명시(사람·AI가 집행 체계를 알게). sync로 전 에이전트 파일 전파.

## §4. 원칙

| 관점 | 적용 |
|------|------|
| **정직한 커버리지 (거짓완료 금지)** | "훅으로 다 잡힘" 금지. §2 매트릭스로 각 겹의 구멍을 명시. ADR/TS는 ②가 못 잡고 ③이 자문으로만 잡음을 숨기지 않음. |
| **차단은 결정적 신호만** | ②는 세션일지처럼 오탐 없는 검사만 차단. ADR/TS 같은 의미판단은 차단 부적합 → 자문(③). 과안정화(RFC 0051 원칙) 계승. |
| **마찰 귀착 = AI** | 커밋 훅 마찰은 커밋 실행자(AI)가 받게 설계 → 사람 짜증 없음. 우회로(`[skip-record]`)는 유지(사소 커밋 봉쇄 방지). |
| **도구 불가지론 (VHK 차별축)** | git 훅·규칙 문구 = 도구 무관. Claude 전용 훅 회피. |

## §5. 열린 결정 (구현 전 확정)

1. **커밋 훅 배선 방식**: `.git/hooks` 직접 vs `core.hooksPath=.vhk/hooks`. 후자가 git init 타이밍·버전관리에 유리해 보이나 기존 사용자 hooksPath 덮을 위험. [확신 낮음 — 조사 필요]
2. **T2 백스톱의 백스톱**(다음 세션 공백 알림)을 IN/OUT — 과설계 경계. handoff 커버율을 먼저 측정하고 판단 권장.
3. **차단 vs 경고 강도**: ②를 hard block으로 할지, 경고+통과로 할지. 사용자 니즈("짚어주기 제거")는 block이 강하나, 초보 프로젝트엔 `[skip-record]` 남발로 무력화 우려. → block + AI지시서 조합이 기본, 실측으로 조정.

## §6. 위험 / 엣지

- **git init 전 훅 무효**: §3 T1 배선 시점 문제. 미해결이면 훅이 조용히 안 걸림 → 배선 후 self-test로 확인.
- **[skip-record] 남발**: 우회로가 규칙을 형해화. 완화 = 남발 감지는 하지 않음(사용자 자율), 대신 ③ 수확이 2차로 잡음.
- **오탐 차단으로 커밋 지옥**: ②가 결정적 검사만 하면 오탐 최소. 그래도 막히면 `[skip-record]` 즉시 우회.
- **저품질 에이전트가 지시서 무시**: ②가 사람에게 노출됨 → ③이 백스톱. ②③ 실전 커버율은 다음 독푸딩으로 측정(recall 라벨·계측 DB 활용).

## §7. 구현 전 확인 항목 (사실 미확정)

1. 새 프로젝트 배출 `CLAUDE.md`가 "세션 종료 = `vhk work handoff`" 의례를 실제로 지시하는지 — Wave 1 감사에서 미확인. RFC 0061 첫 작업으로 grep 확인.
2. vhk 본체 `check-records` hook 구현 실체(`scripts/` 또는 `.git/hooks`)를 읽고 이식 가능 형태 파악.
3. `core.hooksPath` 접근이 기존 사용자 훅과 충돌하지 않는 안전 배선인지.

## §8. 성공 기준

- 새 프로젝트에서 src 변경 + 세션일지 누락 커밋이 **차단**되고, 에러가 AI 작업지시서 형태(라이브 실측).
- `[skip-record]` 커밋은 통과.
- handoff가 미기록 ADR/TS 후보를 프롬프트에 노출(RFC 0051 회귀 green).
- **최종 지표(다음 독푸딩)**: 기록 관련 수정지시 0회(RFC 0060과 공유 지표).
