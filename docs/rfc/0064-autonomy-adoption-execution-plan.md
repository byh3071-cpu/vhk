## 2. goal 110·111 착수 계획 (골 사이클)

### 2.1 순서·의존성
111의 계측 필드는 110이 확장하는 autonomy-log 스키마 위에 얹힘 → **직렬**. 각 goal = 1 iteration(1 goal + 작은 commit + 게이트).

### 2.2 단계 매핑 — 현재 위치: 조사 완료·스펙 절반

| 골 사이클 단계 | 110 | 111 |

### 2.3 라우팅·게이트
- 파일수 결정론: 110 ≈ 5~6파일 / 111 ≈ 4~5파일 → 둘 다 **M**(탐색→계획 승인→구현 sonnet→적대검증 opus 루프). orca L 불필요(단일 레포·기존 모듈 확장).
- 공통 게이트: build·test·**lint**(로컬 게이트에 lint 포함 — CI 정합) + check-goal-10N + 세션 dev log + PR(머지=사람).
- DoD: 110 = 기존 jsonl 하위호환 + 3중 확인 기준 완주율 재계산(표본 0 정직 표기) / 111 = 3+1필드 + 3문답 추적 시간 1문항 + stats 병목 섹션. GA 시그니처 보존(신규 필드 전부 optional).
- 예상: 110 = 스펙·설계 승인 30분 + 구현 1세션 / 111 = 1세션(스키마 전제 확정 후).

1. PR#532 머지 확인 → `vhk work` 시작.

## 3. GTM 게시 판단 (리서치 결정 4 연계)

### 3.1 현황 (실측 — §1 정찰)
잔여 작업 = ①블로그 published:true 전환+라이브 검증 ②Show HN 초안의 스펙 대조 최종 검수+**첫 코멘트 동시 산출**(스펙상 강한 관행) ③긱뉴스 변환본 신규 생성(스펙: 언어 유지·"Show GN:" 직접 타이핑 금지·계정 가입 1주 경과 필요) ④exports 정규 경로(`yohan-studio/docs/content/exports/vhk-record-gate/`) 정리 ⑤게시 버튼 = 사람.

### 3.2 게시 찬성 근거 (객관)
1. **창 닫힘 실측**: 리서치 결정 4 — MS AGT(4.9k★)·Haystack(YC)·스텔스 신규 진입이 4방향 압착. "1인용 CLI+완료검증" 교집합은 아직 비었으나 선점 창은 시간에 반비례.
2. **포지셔닝 근거 보강**: Show HN 초안 추천 제목("catch AI false completions with machine evidence, not LLM judgment")이 리서치 검증 수치(LLM judge AUROC<0.65·거짓완료=실패의 45~76%, arXiv 2건 실재 확인)와 정확히 일치 — 예상 질문("왜 LLM 리뷰로 안 되나")에 인용 가능한 학술 답변 확보. 이번 세션의 포워더 위조 적발 실화도 1인칭 사례로 사용 가능.
3. **재료 완비**: 리프레임 이미 반영·마스터 MDX 존재·진입점 배선 완료 — 잔여는 기계적 변환+버튼.
4. **Phase 2 exit 마지막 조각**(roadmap 실측) — 게시 1회가 로드맵 전진 조건.

### 3.3 보류·주의 근거 (객관)
1. 게시 직후 코멘트 대응 시간 필요 — 주 10~20h(저녁·주말) 제약 → **버튼은 주말 시작 시점**이 합리적(HN 트래픽 고려보다 대응 가용성 우선).
2. 긱뉴스 계정 가입 1주 경과 조건 — **미확인**(오너 계정 상태 모름).
3. Show HN 도메인 밴 리스크 — upvote 동원 금지 등 스펙 준수 필수(스펙 문서 존재로 통제 가능).
4. 익명 노선 — 초안·코멘트에 실명·소속 부재 확인 필요(검수 항목).

### 3.4 판단·권고
**게시 GO — 단 2단 분리**: (a) 게시 준비 패키지(긱뉴스 변환+Show HN 스펙 검수·첫 코멘트 초안+exports 정리+블로그 published 전환 PR)는 **다음 세션에서 AI가 즉시**(studio-post 스킬 절차) → (b) 실제 버튼 3개(블로그 발행 확인·HN 제출·긱뉴스 제출)는 **오너가 주말**. 미확인 2건(긱뉴스 계정 경과일·주말 가용 시간)만 오너 확인 필요. 110 구현과 병행 가능(코드/콘텐츠 독립) — 단 같은 주말에 몰리면 버튼 우선.
