## 2. 순서 원칙

2차 도그푸딩이 처방을 이미 써놨다.

> 다음 버전이 갈 방향은 기능 추가가 아니라 **기존 기능의 실행 조건을 사람 손에서 떼는 것**이다.

```
선행: 복구·위생 ─▶ 2.13 첫 실행 신뢰 ─▶ 2.14 규칙을 검사로 ─▶ 2.15 권고가 안 죽게
                                                                      │
                                                                      ▼
2.19 승인 경계 ◀─ 2.18 실행 레인 ◀─ 2.17 권한 단계 ◀─ 2.16 측정기
      │
      └─▶ 3채널 게시 (사람)
```

| 왜 이 순서인가 | 근거 |
|---|---|
| 선행이 맨 앞 | 작업 카드의 유일 사본이 비추적 경로에만 있었다. 되돌릴 수 없는 유일한 항목 |
| 2.13이 그다음 | `check`가 필수 규칙을 금지로 뒤집고 `doctor`가 영구 오판하는 상태 위에는 무엇을 쌓아도 신뢰가 안 선다 |
| 2.14가 최대 공백 | 설계 축 3단계(원본 → 전파 → 차단) 중 3번이 비어 있다. 규칙 40여 줄 중 기계 검사 1개 |
| 2.16이 2.17보다 앞 | ADR-009 ①: "실행 기능보다 권한 계측·검사 관리 먼저" |
| 2.17~2.19는 기본 off | 외부 실행력 재개 조건 3개 미충족. 만들되 켜지 않는다 |
