# 2026-07-13 — RFC 0062 구현: 문서-실측 드리프트 자동감지 (warn 모드)

## 결론
사용자 승인 직후 RFC 0062 warn 모드 구현. `vhk sync --check` 가 규칙 sync 드리프트에 더해 **문서-실측 드리프트 3계열**(수치/RFC 헤더 상호참조 모순/블로커 모순)을 warn 으로 보고하고 `.vhk/events/drift-log.jsonl` 에 계측을 쌓는다. 차단 0 — fail 승격은 오탐률 실측 후 사람 판정(measure-first).

## 구현
- `src/lib/drift-pairs.ts` — 검사 등록부+3계열: A 수치(README `**vX.Y.Z**`·CLAUDE LIVE `**버전:**` 줄 ↔ package.json, "MCP N tools" ↔ 실등록 수 주입) / B 상호참조(RFC 헤더 `> 상태:` ↔ 타 문서의 괄호형 archived 지칭) / C 상태 정합("블로커 없음" 선언 ↔ blockers.md 비취소선 항목). 대상 파일 부재 = 검사 부적용(사용자 레포 호환).
- `src/lib/drift-log.ts` — append-only 원장(merge=union 와일드카드 커버 확인).
- `src/commands/sync.ts` — --check 흐름 끝에 `reportDocDrift`(exitCode 불변·검사 자체 오류 fail-open). ko.ts 4키, COMMANDS.md.

## 첫 라이브가 곧 실전 (§6 원칙 발동)
- 자기 레포 첫 실행에서 **발견 2건 → 판정: 둘 다 오탐** — 근접(40자) 패턴이 "0056·0057**이** archived로 지칭"(주체) 을 "0056 이 archived 다"(대상)로 오독. §6("오탐=신뢰 사망, 애매하면 검사 안 함")대로 괄호형 지칭(`RFC 0055(Proof Protocol, archived)`)으로 즉시 조임 → 재실행 오탐 0.
- 오탐→조임 이력이 drift-log 원장에 그대로 남음(crossref 2 → 0) — warn 모드 계측의 존재 이유를 첫날 실증.
