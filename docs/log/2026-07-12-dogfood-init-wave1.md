## 교훈
- **버전 안 올리고 누적하면 "만든 기능이 사용자에게 없음"이 비가시화된다** — 미발행 누적분은 버전 드리프트 가드로도 안 잡힘(버전을 안 올렸으니). 독푸딩을 낡은 발행본으로 하면 개선이 헛돎. 작은 fix라도 발행 주기를 짧게.

### Wave 2 RFC 2개 (Draft)
- **RFC 0060 — init 기록 온보딩**: `[여기에 작성: 질문]` 관행 마커(PRD·ARCHITECTURE 한정) + 상단 가드("AI 추측 금지") + 첫 세션 인터뷰 2단계(도메인 4문항 + 기획 슬롯 5±2, VISION 제외) + init 자동 sync(그린필드/adopt승인만) + "설치 점검" 영수증(읽기검증 기반). 트리거 격차는 RFC 0057 §7 계승 → 마커 규칙 문구를 sync로 전 에이전트 전파해 도구 무관 백업 트리거 확보(격차 "축소"지 "소멸" 아님 정직 표기).
- **RFC 0061 — 기록 집행 3겹 그물**: ①규칙선언(배출됨) ②커밋훅(세션일지 누락 100% 차단, 마찰은 AI가 받음) ③세션종료 수확(ADR/TS 의미후보 = RFC 0051 이식). 훅 단독이 반쪽인 이유(의미판단 불가)를 §2 매트릭스로 정직 명시. git 훅이라 도구 불가지론.
- 채번: 0059는 next-task가 UX 단순화용으로 예약 → 0060·0061 사용.
- **HARD-GATE**: 둘 다 Draft. 구현 전 사용자 승인 + §7 확인 항목(새 프로젝트 CLAUDE.md handoff 의례 지시 여부 등) 실측 필요.

### 교훈(append)
- **"한방" 주장은 영수증으로만 닫는다** — 자동 sync가 브라운필드에서 남의 파일 덮을 위험을 발견(RFC 0060 §2). "한방=편의"가 "한방=파괴"가 되지 않게 그린필드/adopt 게이트 필수. 편의 기능일수록 안전 게이트를 먼저 설계.
- **집행 훅의 유혹 = 거짓완료 위험** — "커밋 훅 하나로 기록 다 잡음"은 매력적이나 의미판단(ADR감 여부)은 기계가 못 함. 커버리지를 부풀리지 않고 겹별 구멍을 매트릭스로 드러내는 게 정직.
