사용자(백요한) 요청: "vhk로 프로젝트 초기화 시 노션 바이브코딩 스타터킷의 docs 문서들이 잘 배출되는지 확인 + 누락·보완점".

## 감사 결과 (증거 기반)
- **로컬 HEAD init**: 26파일 정상 배출(멱등성·이름치환·sync·NEEDS_CUSTOMIZATION·SessionStart 훅 전부 정상).
- **P1 발행 격차**: npm 발행본 v2.9.0이 origin/main 대비 21커밋 뒤처짐. 버전 숫자가 둘 다 "2.9.0"이라 격차 비가시. → 실사용자는 goal 88~100 기록 인프라를 못 받음.
- **P1 죽은 안내문**: init 완료 후 "다음에 할 일" 1번이 `👉 여기를 채워주세요` 마커를 찾으라 안내하나, 어떤 생성 파일에도 그 마커 없음(`ko.ts:205,209`에만 존재, 템플릿 grep 0건). 비개발자 첫걸음 헛수색.
- **P2 sync 안내 부재**: init next-steps에 `vhk sync` 없음 → AGENTS.md가 sync 전까지 부재 → Codex·Zed 등 AGENTS.md 인식 에이전트가 규칙 없이 시작.
- **P2 brain-root 미설정**: 요한 머신에서 매 init마다 core-rules 번들 v0.1.0 폴백 경고.
- **노션 8곳 어긋남**: 버전 callout(v2.7.0/MCP30)·`secure guard`(존재 안 함)·runbook 행·"4계층"(실제 6섹션)·learnings.md "vhk learn"(v2 동결) 등.

## 스코프 결정 (사용자 승인)
- **2릴리즈 전략**: v2.10.0 = 현 HEAD + 죽은 안내문 최소수정 즉시 발행(Wave 1). v2.11.0 = `[여기에 작성:]` 마커 + 인터뷰 2단계 + 설치점검 영수증(Wave 2, 본공사).
- **에이전트불가지론 트리거 격차는 RFC 0057에 합류**(별도 RFC 분기 방지).

## 교훈
- **버전 안 올리고 누적하면 "만든 기능이 사용자에게 없음"이 비가시화된다** — 미발행 누적분은 버전 드리프트 가드로도 안 잡힘(버전을 안 올렸으니). 독푸딩을 낡은 발행본으로 하면 개선이 헛돎. 작은 fix라도 발행 주기를 짧게.
- **UI 안내 문구도 "거짓완료"의 일종** — "채우세요"라 했는데 채울 마커가 없으면 사용자 신뢰가 첫 화면에서 깨진다. 안내가 가리키는 대상의 실재를 테스트로 잠가야 한다.
