# 2026-07-13 — RFC 0061 T1~T3 구현: 기록 집행 커밋훅(record-net)

## 결론
사용자 승인(2026-07-13) 직후 RFC 0061 3트랙 구현. 새 프로젝트가 `vhk init` 만 하면 **세션일지 없는 실질 코드변경 커밋이 git 수준에서 차단**되고(도구 불가지론 — Claude/Cursor/Codex 무관), 에러가 AI 작업지시서로 나가 AI 가 일지 쓰고 재커밋하는 루프가 성립.

## §7 사전확인 결과 (구현 전 사실 확정)
1. 새 프로젝트 CLAUDE.md 템플릿에 handoff 의례 **없음**(recap 만) → T2 필요 확정.
2. vhk 본체 check-records = **Claude Code PreToolUse 훅**(`scripts/check-records.mjs --hook`) — Claude 전용임을 확인. 판정부(evaluateRecords)가 순수함수라 이식 가능.
3. core.hooksPath = 기존 사용자 훅(husky 등) 전체 무력화 위험 → 기각, `.git/hooks` 직접+마커 소유권으로 확정(§5-1).

## 구현
- **T1**: `src/templates/record-hook.ts`(RECORD_CHECK_TEMPLATE = `.vhk/hooks/record-check.mjs` 자립형 판정, COMMIT_MSG_HOOK_TEMPLATE = `.git/hooks/commit-msg` shim) + `src/lib/record-hook.ts`(installRecordCommitMsgHook — installed/updated/respected-existing/no-git) + init.ts 배선(파일맵+writeInitExtras) + ko.ts 3메시지.
  - commit-msg 훅 선택 근거: pre-commit 은 메시지를 못 봐 `[skip-record]` 판정 불가.
  - fail-open 3중: node 부재·스크립트 부재(shim)·게이트 내부 오류(스크립트) → 전부 통과. HARD_STOP 은 우회 토큰보다 먼저 차단.
  - 본체 교훈 이식: LF 고정(셔뱅+CRLF Windows 전멸), core.quotepath=false(한글 일지 false block), 과안정화 경계(src/** 만, 문서·테스트 커밋 불간섭).
- **T2+T3**: rules-md.ts §기록 규칙에 handoff 의례 + 3겹 그물 명시, claude-md.ts 세션 종료에 handoff 병기.
- RFC 0061 헤더 Draft→Accepted + §5 열린 결정 3건 확정 기록.
