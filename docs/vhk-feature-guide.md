# VHK 기능 안내 (쉬운말 버전)

> 비개발자용. "이 기능이 언제·왜 쓰는 건지" 중심. 명령 이름은 그대로 두되 설명은 일상어로.
> 정확한 버전·테스트·MCP 도구 수 같은 숫자는 `package.json`·`CHANGELOG.md`가 진짜 기준.
> 이 문서는 코드를 직접 읽어 정리한 것 — 마케팅 문구 아님.

---

## VHK가 한 줄로 뭐냐

**AI 코딩 세션을 "목표·증거·기억·규칙" 네 가지로 묶어주는 한국어 안전벨트.**
AI가 빨리 만든 결과를 그냥 믿지 않고 — "뭘 하기로 했나, 진짜 끝났나, 다음에 어디서 이어가나"를 파일과 검사로 고정한다. VHK는 코딩하는 AI가 아니라, 코딩하는 AI를 **감독·기록**하는 도구다.

---

## 🌅 일 시작할 때

| 명령 | 쉬운 설명 |
|------|-----------|
| `vhk work` | **"자, 시작"** 버튼. 지금 코드 상태·할 일·규칙을 한 덩어리로 묶어 복사 → Claude에 붙여넣으면 바로 이어서 작업. 매일 아침 첫 단추. |
| `vhk start` | 완전 새 프로젝트 깔 때 한 번. 필관리자 파일·설정 자동 생성(설치 마법사). |
| `vhk standup` | 아침 브리핑. "어제 뭐 했지? 오늘 뭐 하지?" |
| `vhk status` | 지금 상태 한눈에(뭐 바뀌었나·최근에 뭐 했나). 보기만, 안 바꿈. |

## ⚙️ 일하는 중

| 명령 | 쉬운 설명 |
|------|-----------|
| `vhk goal` | 할 일을 단계별 "목표"로 쪼개 관리. 다음 목표 자동 추천(`next`), 끝나면 완료처리(`done`). |
| `vhk mission` | "이번엔 여기까지만 건드린다" 범위 약속. 딴 데 손대면 경고. |
| `vhk check` | 정해둔 규칙 어겼나 자동 점검. |
| `vhk context` / `vhk brief` | Claude한테 "이 프로젝트가 뭔지" 알려주는 설명서 파일 생성. |

## 💾 저장·정리할 때

| 명령 | 쉬운 설명 |
|------|-----------|
| `vhk save` | 저장 버튼. 시크릿 노출 검사 → 저장 → 업로드 한 번에. |
| `vhk recap` | 하루 끝 일기. 오늘 한 일·결정 기록 + 중관리자 결정은 자동으로 문서 후보로 뽑아줌. |
| `vhk work handoff` | 중간에 끊을 때 "여기까지 했고 다음은 이거" 인수인계 메모. |
| `vhk today` | 저녁 자축. "오늘 이만큼 했어" + 격려 한마디. |

## ✅ "진짜 다 됐나?" 검증 — VHK 핵심

| 명령 | 쉬운 설명 |
|------|-----------|
| `vhk verify` | 진짜로 빌드·테스트·보안검사를 **돌려보고** 결과를 증거로 남김. 말만 "됐어"는 안 통함. |
| `vhk review` | **거짓완료 잡는 심문관.** 증거랑 목표 완료조건을 대조해 "끝난 척하는 거 아냐?" 캐물음. 애매하면 "확실 아님"이라 정직하게 표시. |
| `vhk preflight` | 배포 직전 8가지 안전점검. 하나라도 심각하면 막음(우회 불가). |
| `vhk audit` | 외부 패키지에 알려진 보안 구멍 있나 검사. |
| `vhk doctor` | 개발환경 건강검진(Node·git·MCP 등 정상인지). |

## 🛡️ 안전장치 (사고 방지)

| 기능 | 쉬운 설명 |
|------|-----------|
| HARD_STOP (`vhk blocker` / `vhk resume`) | 비상 정지 스위치. 문제 3번 쌓이면 자동으로 걸려 작업 중단. **사람이 직접** `vhk resume --confirm` 해야만 풀림. |
| 위험작업 가드 | 배포·삭제·발행처럼 되돌리기 힘든 일은 자동 실행 안 하고 꼭 확인받음. |
| `vhk secure` | 코드에 비밀번호·API키 실수로 적어놨나 스캔. |
| `vhk cost` | Claude API 돈 얼마 썼나 추적. 예산 80% 경고·100% 차단. |
| `vhk mode` | 안전 강도 조절(lite=느슨 / standard=기본 / strict=빡빡). |

## 🧠 기억·학습 (점점 똑똑해짐)

| 명령 | 쉬운 설명 |
|------|-----------|
| `vhk memory` | 결정·실패·성공·패턴 4종류로 기억 저장. |
| `vhk learn` | "이런 실수 다신 말자" 교훈 한 줄 기록. |
| recall (자동) | 비슷한 상황 오면 과거 교훈 자동으로 꺼내 경고. |
| `vhk pattern` / `vhk evolve` | 반복되는 실패를 감지 → 아예 규칙으로 만들어 RULES.md에 추가(자기개선 고리). |

## 📤 규칙 동기화·배포

| 명령 | 쉬운 설명 |
|------|-----------|
| `vhk sync` | **간판 기능.** 규칙 한 곳(RULES.md)만 고치면 Cursor·Claude·Copilot 등 여러 AI 도구 설정 자동 통일. |
| `vhk deploy` | 배포(Vercel·Netlify·Cloudflare 자동 감지). |
| `vhk publish` | npm 발행(3중 안전가드 — main에서만, 사람 승인). |
| `vhk ship` | 배포 체크리스트 + 회고. |
| `vhk cloud` | 내 설정을 GitHub 비밀 저장소에 백업·복원. |
| `vhk undo` / `vhk restore` | 되돌리기 / 백업에서 복구. |

## 🔧 부가 기능

| 명령 | 쉬운 설명 |
|------|-----------|
| `vhk diff-cover` / `vhk testmap` | 바꾼 코드에 테스트 있나 점검. |

## VHK를 관통하는 설계 철학 3가지

1. **거짓완료 차단** — `verify`는 항상 증거 기록, `review`는 적대적 심문. "0개 발견 = 안전"같은 거짓 추론을 막는다.
2. **사람을 결정경로에** — 되돌리기 힘든 일(배포·발행·삭제)은 AI/자동에서 빼고, 안전 가드 통과 필수. HARD_STOP은 사람만 해제.
3. **정직한 측정** — 증명 전엔 무거운 기술(ML 등) 금지, 검사 불완전하면 "불완전"이라 표시, 모르면 "모름"으로 분류.
