# AI 코딩 도구를 바꿀 때마다, 왜 매번 처음부터 다시 설명할까

> 이 글은 도구 자랑이 아니라, 한 가지 반복되는 통증에 관한 이야기다.

## 장면 하나

Cursor 로 잘 쓰던 프로젝트가 있다. 코딩 규칙, 기술 스택, 하지 말아야 할 것들을
`.cursorrules` 에 정성껏 적어뒀다. 어느 날 Claude 로 갈아탄다. 그런데 Claude 는
`.cursorrules` 를 안 본다. `CLAUDE.md` 가 필요하다. 같은 규칙을 **다시 적는다.**

며칠 뒤 Windsurf 를 시험해본다. 또 다른 파일(`.windsurfrules`). **또 적는다.**
규칙은 하나인데, 파일은 도구 수만큼 늘어난다. 그리고 규칙을 한 번 고치면,
그 모든 파일을 **손으로 따라 고쳐야** 한다.

## 장면 둘

새 노트북을 샀다. 코드는 `git clone` 하면 된다. 그런데 그동안 머릿속에 쌓아둔 것들 —
"이 API 는 왜 tRPC 로 갔는지", "이 폴더는 건드리면 안 되는 이유", "지난주에 막혔던 그 결정" —
이건 clone 으로 안 온다. AI 에게 다시 브리핑한다. **프로젝트의 기억이 기기와 함께 죽는다.**

## 진짜 비용은 "다시 설명하는 시간"이 아니다

다시 적는 10분이 아깝다는 얘기가 아니다. 진짜 비용은 **드리프트**다.

- 도구마다 규칙 파일이 갈라지면, 어느 게 최신인지 아무도 모른다.
- 한 곳만 고치고 나머지를 깜빡하면, 도구마다 **다른 규칙**으로 코드를 짠다.
- 맥락이 매번 리셋되면, AI 는 매번 **조금씩 다른 가정**으로 일한다.

규칙과 맥락이 흩어질수록, "AI 가 알아서 잘하겠지"의 신뢰가 깎인다.

## 그래서 분리해서 생각해봤다 — 규칙과 맥락

VHK 가 잡으려는 건 두 갈래다.

### 규칙(rules) — 한 벌로 써서, 도구별로 내보낸다

`RULES.md` 한 곳에 규칙을 적는다. `vhk sync` 가 그걸 `.cursorrules`·`CLAUDE.md`·
`.windsurfrules`·`.github/copilot-instructions.md`·`.agents/rules/`(Antigravity) 로
**동시에 생성**한다. 규칙을 고치면 `RULES.md` 만 고치고 다시 sync 한다.
도구를 바꿔도 규칙은 따라온다 — 손으로 복사하지 않고.

### 맥락(context) — 한 곳에 모아서, 기기 간에 옮긴다

프로젝트의 맥락·결정·브리핑은 `.vhk/` 폴더에 모인다. `vhk cloud push` 로 백업하고,
새 기기에서 `vhk cloud pull` 로 불러온다. 코드는 `git clone`, 맥락은 `cloud pull` —
둘을 합치면 새 컴퓨터에서도 프로젝트의 기억이 살아난다.

## 정직하게 — 자동이 아니라 "명령"이다

오해를 막기 위해 분명히 해둔다.

- 이건 **마법이 아니다.** 규칙은 `vhk sync`, 맥락은 `vhk cloud pull` — 옮길 때
  **명령을 친다.** "아무것도 안 해도 따라온다"가 아니라 "다시 만들지 않고 불러온다"이다.
- **개인 메모와 참고링크는 백업에서 기본 제외된다.** 클라우드 백업은 GitHub gist 를 쓰는데,
  gist 주소를 아는 사람은 내용을 볼 수 있다. 그래서 민감할 수 있는 개인 메모(`memory.json`)·
  참고링크(`refs.json`)는 **처음부터 백업에 넣지 않는 것**이 프라이버시 장치다.
- 동기화 대상 도구는 현재 Cursor·Claude·Windsurf·GitHub Copilot·Antigravity 5종(v1.4.0)이며,
  계속 넓혀가는 중이다. 각 도구의 규칙 파일 경로·포맷은 공식 문서 기준으로 생성한다.

## 마무리

도구는 계속 바뀔 것이다. 더 좋은 게 나오면 갈아타는 게 맞다. 문제는 **갈아탈 때마다
프로젝트의 기억을 버리고 가야 하는 것**이다.

규칙은 한 벌로, 맥락은 한 곳에 — 그리고 옮길 땐 명령 하나로 불러온다.
그게 "도구를 바꿔도 프로젝트는 그대로"의 의미다.
