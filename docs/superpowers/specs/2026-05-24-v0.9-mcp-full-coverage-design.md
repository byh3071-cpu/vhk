# VHK CLI v0.9 — MCP 풀 커버리지 Design Spec

**Date:** 2026-05-24
**Branch (TBD):** `feat/v0.9-mcp-full-coverage`
**Baseline:** main `c1c54ea` (v0.8.1 post-release, NL/exec/version/publish fix 모두 반영)

## Goal

Cursor 사용자가 자연어로 vhk의 **모든 자동화 가능 명령**을 호출할 수 있게 한다.

현재 MCP 노출 10개 → v0.9에 6개 추가 → **총 16 tools**.

publish는 OTP/2FA 입력이 필수라 MCP 호출 의미 없음 → CLI 전용으로 유지. design-palette는 design의 alias라 MCP에서는 중복 → design 단일 tool.

## Out of Scope

- `publish` MCP 노출 (OTP/2FA 요구 → CLI 전용 유지, MCP 설명에 안내 메시지 노출)
- `design-palette` MCP tool (design tool의 palette 인자로 통합)
- v0.6의 기존 10 tools (save/undo/status/diff/ship/doctor/check/recap/env/env-check) 리팩토링 — server.ts 인라인 유지, v0.9에서 건드리지 않음
- v0.8 보류 과제: design ↔ theme 토큰 연동, ref add NL 진입점 — v0.10+
- 다른 IDE 지원 (Windsurf/Zed/VSCode) — v0.10+

## Architecture

### 명령 함수 시그니처 변경 (refactor)

각 명령 함수가 옵션 인자를 받도록 확장. **인자 있으면 비대화, 없으면 기존 inquirer 대화형 폴백.** 단일 코드패스로 CLI + MCP 둘 다 커버.

```ts
// src/commands/design.ts
export interface DesignOptions {
  palette?: 'Minimal' | 'Vibrant' | 'Corporate' | 'Pastel'
  overwrite?: boolean
}

export async function design(opts?: DesignOptions): Promise<void> {
  const paletteIndex = opts?.palette
    ? PALETTES.findIndex(p => p.name === opts.palette)
    : (await inquirer.prompt([...])).paletteIndex
  // ...
}
```

CLI 호출 (`vhk design`) → `design()` → inquirer 그대로.
MCP 호출 → `design({ palette: 'Minimal', overwrite: false })` → prompt skip.

### 디렉토리 구조

기존 `src/mcp/server.ts` 인라인 10 tools 유지 + 신규 6 tools는 `src/mcp/handlers/` 분리:

```
src/mcp/
├── server.ts                  ← 기존 10 tool 인라인 + 신규 6개 import·register
└── handlers/
    ├── deploy.ts              ← deploy tool
    ├── design.ts              ← design tool
    ├── theme.ts               ← theme tool
    └── ref.ts                 ← ref_add / ref_list / ref_open 3개
```

handler 파일 시그니처:

```ts
// src/mcp/handlers/design.ts
import type { McpServer } from '@modelcontextprotocol/sdk/server/mcp.js'
import { z } from 'zod'
import { design } from '../../commands/design.js'

export function registerDesignTool(server: McpServer): void {
  server.registerTool(
    'design',
    {
      description: '디자인 토큰 생성 (CSS 변수 또는 Tailwind config)',
      inputSchema: {
        palette: z.enum(['Minimal', 'Vibrant', 'Corporate', 'Pastel']).optional()
          .describe('컬러 팔레트 (생략 시 Minimal 기본)'),
        overwrite: z.boolean().optional().describe('기존 파일 덮어쓰기 (기본 false)'),
      },
    },
    async ({ palette, overwrite }) => {
      try {
        await design({ palette, overwrite })
        return { content: [{ type: 'text', text: `✅ 디자인 토큰 생성 완료 (palette: ${palette ?? 'Minimal'})` }] }
      } catch (err) {
        const msg = err instanceof Error ? err.message : String(err)
        return { content: [{ type: 'text', text: `❌ 실패: ${msg}` }], isError: true }
      }
    }
  )
}
```

`server.ts` 변경:
```ts
import { registerDeployTool } from './handlers/deploy.js'
import { registerDesignTool } from './handlers/design.js'
import { registerThemeTool } from './handlers/theme.js'
import { registerRefTools } from './handlers/ref.js'

// ... 기존 10 tool 등록 후
registerDeployTool(server)
registerDesignTool(server)
registerThemeTool(server)
registerRefTools(server)
```

## Per-Tool Specs

### 1. `design`

| 항목 | 값 |
|------|-----|
| description | 디자인 토큰 생성 (CSS 변수 또는 Tailwind config) |
| inputSchema | `palette?: 'Minimal'\|'Vibrant'\|'Corporate'\|'Pastel'`, `overwrite?: boolean` |
| 동작 | `design({palette, overwrite})` 호출 |
| 출력 | `✅ 디자인 토큰 생성 완료 (palette: X) — src/styles/{tokens.css\|vhk-colors.ts}` |
| 충돌 | `overwrite=false`이고 기존 파일 존재 → `⚠️ 이미 존재. overwrite:true로 다시 호출하세요.` 반환 |

### 2. `theme`

| 항목 | 값 |
|------|-----|
| description | 다크/라이트 모드 CSS + 토글 유틸 생성 |
| inputSchema | `overwrite?: boolean` |
| 동작 | `theme({overwrite})` 호출 |
| 출력 | `✅ 테마 파일 생성 완료 — src/styles/theme.css, src/lib/theme-toggle.ts` |

### 3. `ref_add`

| 항목 | 값 |
|------|-----|
| description | 레퍼런스 URL 추가 (.vhk/refs.json) |
| inputSchema | `url: string` (필수), `memo?: string` |
| 동작 | `refAdd(url, memo)` 호출 (현재 인터페이스 그대로) |
| 출력 | `✅ 추가됨 (#N) — <url>` |

### 4. `ref_list`

| 항목 | 값 |
|------|-----|
| description | 저장된 레퍼런스 목록 |
| inputSchema | (없음) |
| 동작 | `refList()` 호출, 결과 캡처 후 텍스트 반환 |
| 출력 | `📚 총 N개:\n  [1] url — memo\n  ...` |

### 5. `ref_open`

| 항목 | 값 |
|------|-----|
| description | 레퍼런스를 브라우저에서 열기 |
| inputSchema | `index: number` (필수, 1-based) |
| 동작 | `refOpen(String(index))` 호출 — safeExecFile 기반 launcher |
| 출력 | `🌐 열기: <url>` 또는 `❌ 유효하지 않은 번호` |

### 6. `deploy`

| 항목 | 값 |
|------|-----|
| description | 프로덕션 배포 (Vercel/Netlify/Cloudflare 자동 감지) |
| inputSchema | `platform?: 'vercel'\|'netlify'\|'cloudflare'`, `skipConfirm?: boolean` |
| 동작 | `deploy({platform, skipConfirm})` 호출 |
| 출력 | `🚀 배포 시작...` + 최종 URL/에러 (긴 로그는 trim, 마지막 30줄 + 핵심 요약) |
| stdio | **safeExecFile (stdio:pipe)로 캡처** — MCP JSON-RPC 충돌 회피. CLI는 기존 safeExecFileStream 유지 |

deploy 명령 자체에 `opts?.captureOutput` 같은 모드 분기는 두지 않고, **CLI와 MCP 둘 다 인자 받아 동작** + **출력은 항상 stdout 전달**. MCP 핸들러에서 자식 프로세스 출력을 자체 capture 처리.

## Command Function Refactor Plan

### `src/commands/design.ts`

```ts
export interface DesignOptions {
  palette?: 'Minimal' | 'Vibrant' | 'Corporate' | 'Pastel'
  overwrite?: boolean
}
export async function design(opts?: DesignOptions): Promise<void>
export async function designPalette(opts?: DesignOptions): Promise<void>  // 동일 인자 전달
```

### `src/commands/theme.ts`

```ts
export interface ThemeOptions {
  overwrite?: boolean
}
export async function theme(opts?: ThemeOptions): Promise<void>
```

### `src/commands/ref.ts`

이미 인자 받음 (`refAdd(url, memo)`, `refOpen(indexStr)`). 변경 없음.

### `src/commands/deploy.ts`

```ts
export interface DeployOptions {
  platform?: 'vercel' | 'netlify' | 'cloudflare'
  skipConfirm?: boolean
}
export async function deploy(opts?: DeployOptions): Promise<void>
```

기존 deploy 구현체에 플랫폼 자동 감지 + skipConfirm 분기 추가 (확인 prompt 우회).

## Backward Compatibility

- `vhk design` / `vhk theme` 등 CLI 인자 없는 호출 → 기존 동작 (inquirer 대화형) 그대로
- 옵션 추가는 모두 optional → 기존 호출자 영향 없음
- 기존 MCP 10 tools 그대로 (server.ts 변경 최소: import + register 4줄 추가)
- `src/index.ts` commander 명령 등록 변경 없음 — 모든 register는 `await action()` 시 인자 없음 그대로

### 명령 함수 refactor 회귀 테스트
